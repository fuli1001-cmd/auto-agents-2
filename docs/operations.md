# 运行与故障处理

## 启动前

运行 `aa2 doctor --project PATH`，确认 profile 存在、模型参数符合本机 CLI、bubblewrap 的实际写入隔离检查通过。`--live` 会消耗 provider 用量，需有可用认证。

保持项目状态目录的私有权限，不将其提交到 Git。配置里的秘密使用受控环境变量或本机 provider 的认证能力。日志不得包含 API key。

## 恢复

中断后运行 `aa2 run --project PATH`。未完成迭代存在时，带需求参数的新命令会直接报错。`status` 显示待处理问题，`respond` 支持从另一终端回复。

控制进程保存原始输入、规格、阶段输出、实现轮次、provider 会话 ID 和验证结果。不要手工删除未完成 run 的状态目录。原始需求文件在快照保存后不再是续跑前提。

自动回退使用 `execution.max_stalled_replans`（默认 2）。首次回退建立验证基线，之后有新增通过的固定验收项且没有退步/检查缺失就继续；连续两次没有可比较的改进则等待用户处理。审查说法改变、源码修改、只打开浏览器页面都不构成进展。查看 `status` 的 `replanning` 和 `logs` 中 `replan.assessed` 可了解回退原因、目标及停滞次数。

停滞提示中的 `y` 只授予再试一次，不清零计数；`n` 保存现场并退出。仅重启或更换 provider 不会重新调用模型绕过等待。人工解决阻塞后可再次 `run` 并确认重试，也可明确调整停滞阈值。

新迭代固定目标分支及其已提交基线。主目录有修改时，先自行提交或保存到其它目录再回复 retry。目标被其它 worktree 占用时先释放。恢复不重新选择基线；中途更改 delivery.target_branch 不改变当前迭代的目标。

主分支在开发期间更新时，会在隔离工作区集成、必要时修复并重新验收。默认最多两次；耗尽后可稳定分支并明确增加 delivery.max_reintegrations，已用次数保持不变。

主目录运行检查另有 `delivery.max_runtime_retries`，默认 3，即首次检查之后最多三次自动尝试。预约在执行前持久化，中断和重启不退款。同一候选、运行输入和失败再次出现时持久化 runtime_blocked；普通 run 或 retry 回复不解除阻塞。处理故障使运行输入改变，或显式增加该设置，才能再次尝试；已用次数保持不变，再次重复失败仍会阻塞。预算耗尽后明确增加该设置只能授予有限额外尝试。无法核实历史运行次数的旧交付日志保留原文，并按当时上限保守占用预算，不能通过升级清零。

研究抓取只连接校验后的公网地址，不继承宿主 HTTP 代理；重定向逐跳验证。浏览器预览只允许当前预览服务的来源，使用受限本地代理约束重定向连接，并限制 WebSocket、弹窗和 service worker。外部 API、字体或资源需要由目标应用按其服务契约提供，不能由模型输出扩大浏览器权限。

交付正常阶段依次是 ready、reintegrating（需要时）、publishing、published、runtime、completion_pending、complete，失败时可进入 repairing_runtime 或 runtime_blocked。成功运行证据在收尾前保存；completion_pending 只重试回执生成、运行入口写入和完成事务，不再调用模型或消耗运行尝试。恢复仍核验源码、HEAD、环境、依赖及证据；身份变化时保留待完成记录并要求核对。发布前中断不重复已验收任务；发布后中断仅继续 Git 恢复与环境交接。Git 的未知锁、未知索引或用户修改会阻止自动修复。不要删除未知 index.lock；先确认其它 Git 进程是否运行。若发布后又创建了用户提交，aa2 保留它并等待人工核对，不会 reset。

发布开始后的 cancel 会暂停收尾。普通 run 会清除这次停止请求并续跑。只有交付回执和当前环境引用一起持久化后，迭代才算成功。

## 环境问题

共享 Conda 环境只允许 EnvironmentManager 安装。依赖更新产生新指纹。失败的环境不会发布 ready 标识，下次按锁定输入重建。Conda 缓存通过子进程配置定向到项目，不修改全局 .condarc。

浏览器启动缺少系统库时优先解决已安装工具链条件；不要执行全局 apt/sudo 安装来绕过项目隔离。可以先在受支持的 Linux/WSL2 主机完成环境准备。

## 清理与空间

自动 GC 在运行中执行。`aa2 gc --dry-run` 可检查候选资源。空间不足时优先删除可再生缓存并降低并发，不能删除活跃工作区或尚未保存的变更。

正式代码位于目标分支和主目录。交付回执（status 可见）关联提交、规格、审批、测试、用量及运行环境。成功后回收工作区、私有 refs/aa2 引用、临时会话、无引用的中间产物；保留回执、用量账本和必要验收证据。

当前运行环境具有交付引用，gc 不会按 TTL 删除它。不要手动删除 .aa2/environments 中当前使用的环境。source .aa2/runtime.sh 使用已准备环境；主目录的 node_modules 和必要构建输出也会保留。

cleanup_pending=true 表示交付已成功但回收需要重试。普通 run 和 gc 均会重试，不再次调用模型。gc --dry-run 按同一引用与 pin 规则报告普通资源候选，不修改状态。手动 GC 的全部删除、私有引用清理和产物压缩均持有 controller.lock；锁忙时明确报错，不执行删除。

## Provider 配置变化

使用 `aa2 provider use NAME` 或 `run --provider NAME`。切换后的选择保存在项目配置；未知实例无法使用。环境变量 null 表示移除继承值，常用于选择 CLI 自身已保存的登录认证。

模型和 effort 从用户 profile 读取。更新用户 profile、可执行文件、完整有效环境（包括继承变量）或实际使用的原生基础配置后，后续调用采用新会话指纹；原生配置和秘密仅参与摘要，不输出其正文。aa2 不自动追踪所谓最新模型。Provider 可执行文件及隐式运行时不能位于被隐藏的项目内；请配置项目外的受信任工具链，公开快照和审核过的附件仍通过显式挂载提供。

状态库当前为 v6，在普通 run 持有控制器锁时迁移，先备份原库，再在同一事务补齐表、索引和旧数据。旧版本或已标记 v3 但缺表的数据库均按真实结构处理；status 等读取入口不迁移。检查器、环境和公开视图升级使旧自动证据重新核验，保留既有实现和预算；源码内容不变的有效人工批准继续保留。

隔离恢复快照拒绝外部可变工作区/资源定位和 Git 配置间接引用，路径中的父级片段先规范化再重绑定。旁路原始数据库和快照清单采用排他创建及 0600 权限。手动浏览器依赖副本仅接受复制树内部的相对链接；外部 workspace 链接须先由操作者准备成独立依赖树。


## 第三轮 OCR 修订后的恢复注意事项

构建发布恢复副本位于 `.aa2/recovery/build_*/journal.json` 及相邻编号目录。发布和回滚同时失败时，原始异常保留，并指出恢复日志位置。不要手动删除这些目录、关联的 tmp 或工作区；`resource_holds` 会在迭代取消/完成及 GC 时继续保护它们。再次核验相同工作区时先恢复日志；发现用户修改或备份内容不匹配则保留现场，不覆盖。只有发布或完整回滚已核实，才释放保留记录。隔离快照复制被持有的恢复资源，仅重绑定日志中的可变工作区地址，保留原数据库和证据正文。

停止命令和控制器通道断开都会请求监督进程清理其工作后代。升级前遗留的存活进程记录没有安全控制通道，程序保留记录并报错；先确认实际进程及启动身份，再由操作者处理。程序不会仅根据旧数字 PID 杀进程。应用预览必须能在 Linux `/proc` 中证明实际 TCP 对端属于受管进程树；无法证明时停止核验，端口冲突最多重启三次，不降低所有权检查。

第三轮曾使用敏感值和别名拦截；该材料准入规则已由下方第四轮路径策略替换。日志仍把秘密文件中的值用于脱敏。非 UTF-8 文件名在 Git/私有状态中无损保存，但模型接口要求先明确重命名这些文件。

本地 pip 包可以通过 wheel 路径或 `--find-links`/`-f` 指向工作区内目录。明确选择的 dist wheel 会复制到环境私有源码并参与指纹；外部路径、受保护输入及不支持的路径选项直接报错。损坏的 instance/ready/Node 标记触发重新准备，仍被旧记录引用的实例不会原地删除。

第三轮逐条核对、与前两轮的关系及未纳入项见 [三轮 OCR 对照](quality-first-implementation.md#第三轮-ocr-核对与三轮对照2026-10-16)。

## 第四轮 OCR 修订后的恢复注意事项

仅保护秘密文件路径：默认 `.env`、除 `.env.example` 外的 `.env.*`、原生认证目录及指定凭据文件；`sensitive_paths` 可补充秘密文件／目录。所有真实秘密必须存入这些位置，代码、测试、文档和示例通过环境／配置变量引用。普通文件与提示词、已批准附件不再按秘密值、相同内容或硬链接身份过滤；把真实秘密写在普通路径会使其发送给模型。日志脱敏独立保留。已有 Git 历史、控制器状态和附件权限边界仍受隔离保护。

新状态库为 v6，运行入口会备份并修复中断留下的部分 v5；status 等只读入口不迁移。升级保留旧实现、预算和审批记录。附着终端在原控制器退出后不会自动解除 PAUSED 或发布期间的取消标记；使用显式 `aa2 run` 恢复。

进程记录的 cleaned 表示监督进程已确认后代清理完成。若启动身份不可读、缺失或清理未确认，记录及挂载目录会保留；不要删除这些记录来绕过恢复检查。控制器等待超时不意味着子进程已经退出，监督进程继续持有清理责任。保存的有效模型结果会等清理确认后复用。

构建恢复使用 preparing/prepared/published/restored 阶段；未完成事务必须核验对应映像才能释放 holds。旧无日志保留记录、输出被外部修改或取消归档失败均保持现场。坏交付回执记录为 cleanup_pending 并保护该运行资源，其他运行仍可进入。交付复验 reserved 可恢复派发；started 无 completed 证据时不能当作尚未消费，需核对保留记录后处理。

文档获取支持有界 gzip/deflate 解压，编码／解码各最多 4 MiB，总获取时间最多 30 秒。原生模型主调用仍按既有约定不设总时限。更新原生 auth 文件后后续调用采用新认证源；源不变时保留 CLI 在镜像中刷新后的凭据。
