## 最小目标与不做项

1. 当前已许可的定向诊断目标、预期产物，以及相关历史结果进入只读诊断输入。
2. 同一故障/责任范围的既有失败观察原件可被实际材料投影和挂载读取；历史失败不是当前通过证据，历史模型诊断仍是未执行提案。
3. 对相同事实的实际已完成诊断统一记账；返回 recheck/repair 等建议本身不算执行进展。随后仍由现有动作选择机制决定修复、重检或计划修订；达到原 NO_PROGRESS_LIMIT=2 时不再新授权相同事实的诊断。已有有效许可保留，重复消费不重复计数。

不增加执行候选脚本、写文件、网络设置或依赖安装权限；不改模型配置，不设模型总超时，不解决任意自然语言新颖性，不扩大为通用规则系统。发布后交付的原有人工/额度边界保留。

## 输入、事实与权威

- `diagnosis_request`：许可 key、动作、责任方及绑定摘要；`proposal` 中的 reason/expected_result 是此次只读调查目标，不能被当作新业务义务、已成立事实或额外权限。
- `history`：复用现有最多 16 条恢复历史；保留实际动作/状态/结果/源身份，当前许可单独展示。诊断结论沿既有 proposal 标注，不从其中提取自称的制品 hash。
- `previous_failure_observations`：仅从控制器存储选择同 run、同 failure_id/origin/task 的已记录观察。展示原 checkpoint、观察身份、源码/运行时身份以及已采集检查/日志/故障原件，不读取日志声称的任意路径。历史版本明确区分，不宣称当前匹配或已验收。选择有界并披露省略量，原数据库记录不删除。
- 原件走现有 ContextPlanner、引用目录、artifact hash 和安全材料准入，不重新实现采集或读取安全检查。缺失/被回收原件必须如实显示不可用，不能替换为假正文。

## 冻结、恢复和无进展语义

新逻辑调用在正常 Engine 冻结点绑定完整交接。重新进入已经冻结的调用时，使用当时已有的交接字段；旧调用没有这些字段则保持缺失，不修改其 frozen context、许可或结果。

真实 Demo6 第9轮已中断且输入被冻结：继续时仍为第9轮原输入，不能因改版擅自换输入或扣新轮次；随后新调用才使用完整交接。现有旧计数保留，不将旧未记账历史伪造成新事件或清零。未完成/取消/传输失败不算完成诊断；同一已完成逻辑 operation 只记一次。已有旧账本不可覆盖。

统一记录每次校验通过的只读诊断完成，使用现有事实 basis 与 operation；建议文本、措辞、许可 reason 和历史计数不能改变 basis。新增实际检查/安装日志、源码或正式计划等事实按现有规则形成新 basis。明确区分“累计诊断次数”和“同事实完成诊断无执行进展次数”。

候选建议是可用下一动作时，记录并不拒绝该 repair/recheck/plan_patch；只影响未来是否还能新授权 diagnose。第二次完成后，决策看到原上限排除结果。若无合法替代动作，沿原 RecoveryPathExhausted 保护性停止。已发出许可不因新展示字段重发或扩大；绑定不一致仍 StateConflict。

## 验收矩阵

| 场景 | 必须结果 |
|---|---|
| 实际 Engine：诊断 recheck，决策 diagnose，输入事实不变 | 两次已完成后 diagnose 不再供新选择；可选原授权 repair/plan_patch 或正常停止 |

| 其他任务、其他 failure、伪造 hash/任意本机路径 | 不因交接获得访问/引用或执行权限 |
| 新的真实日志/检查或计划变更 | 形成相应新事实 basis；累计次数不清零，旧账本保留 |
| 仅理由措辞/提案/计数变化 | 不制造新事实或重置保护 |
| 中断后恢复同轮、已完成许可重放 | 冻结输入不变、结果不重跑、记账幂等 |

## 独立设计审阅后的实现约束

交付和任务的进展 basis 都由 RecoveryProgress.inputs 生成，不能用交付展示上下文替代，否则记录与排除会出现不同身份。新有效诊断在提交完成结果前持久登记 operation/owner/basis/outcome_hash；完成后计数，恢复只补已登记的新事件。旧 completed 没有登记则不追记，未完成旧调用在首次有效完成时正常登记。

历史材料只选择同身份的机器检查、环境故障、候选错误等既有观察字段；不复制历史 proposal 或任意 model_attachment 为新材料根。交付使用其既有 recovery/delivery-policy 和 recovery/delivery 记录并按观察身份去重，任务使用 recovery/failures；feedback 与 runtime_failure 两个既有机器检查封装保留原路径。模型理由、预期结果和诊断结论保留在 proposal 标注下。
