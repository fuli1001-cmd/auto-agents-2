# pytest 私有副本的回收与空间预检

仓库根 `conftest.py` 自动加载 `pytest_support.py`。从仓库运行普通
`.conda-env/bin/python -m pytest …` 即生效，无需专用运行器。插件仅管理本仓库测试
生成的私有副本，不访问生产共享缓存、项目运行状态或旧 `/tmp/pytest-of-*` 目录。

## 生命周期

- 默认容器为系统临时目录下的 `aa2-pytest-<uid>-<仓库绝对路径摘要>`。
  `PYTEST_DEBUG_TEMPROOT` 可选择它的父目录。容器必须属于当前用户、权限为 0700，
  路径不得经过符号链接，父目录必须已存在。
  仓库身份绑定实际加载的 `pytest_support.py` 所在目录；`--rootdir` 仅记录为调用上下文，
  不能把不同 checkout 的现场归为同一所有者。
- `--basetemp=/path/to/container` 选择同样的受管理容器。它不是将被整棵清空的目录：
  必须不存在、为空且为 0700，或已有匹配本仓库的身份标记。非空用户目录和其他仓库的
  容器一律拒绝。实际 `getbasetemp()` 是每次唯一的 `run-<uuid>/work`。
- 每个用例在 setup/call/teardown 报告全部结束后，才删除没有失败的 `tmp_path`。
  `tmpdir` 同样受保护。setup/teardown 的真实失败保留现场，不能由 call 通过推断成功。
  标准 pytest 的 `tmp_path_retention_policy` 不接管这些目录。
- `tmp_path_factory`、`tmpdir_factory` 创建的会话共享内容，直到整个会话成功结束才回收。
  插件使用独立的 pytest 公开工厂对象，内建 tmpdir 清理钩子没有这些目录的引用。
- 失败、收集失败、正常中断及硬崩溃现场默认保留最近 **3** 次、最长 **7** 天；
  `--aa2-temp-keep` / `--aa2-temp-days` 可设正数。按容器内全部已登记的空闲会话共同轮换。
  下一次启动和本次结束都会执行回收；没有后续 pytest 调用时，不会后台定时删除。
  已通过用例已被删除，所以失败现场主要包含失败/未完成用例与必要会话级资源。
- `reports/run-*.json` 与大体积现场独立，默认保留 **200** 份、最长 **90** 天。
  包含 Python/pytest 版本、插件与相关入口文件摘要、Git HEAD、空间探测值、结果计数、
  最多 256 个失败用例及阶段、最后未完成用例、最多 32 条清理错误。它不是完整 JUnit、
  源码快照或永久验收归档；需要长期保留的 JUnit、日志和源码指纹应输出到容器以外。

## 删除边界与并发

仅删除身份标记匹配的 `run-<uuid>`，逐级使用目录描述符和 `O_NOFOLLOW` 定位。
只恢复当前用户拥有的目录权限，先修父目录再处理空子目录；普通文件绝不 chmod，
因此硬链接引用的外部文件权限不变。符号链接只解除链接，不遍历目标。标记和锁必须
是当前用户拥有的单链接普通文件；路径替换、所有权或设备变化会拒绝清理。

容器锁保护登记/轮换，每次会话持续持有独立 flock，支持多个普通 pytest 进程共用
同一容器。大体积内容删除期间保留根身份标记和锁，最终元数据收尾也持容器锁；
清理中途硬退出时，下次启动可继续回收已标记的 `cleaning` 现场。删除及轮换全部完成后
才写入 `passed` 结果。最终收尾若只剩不超过 256 KiB 的已知元数据残根，则保守保留并提示，
不认领没有身份标记的内容；包含载荷的缺标记根仍明确拒绝。

锁空闲不代表没有活跃子进程：回收还检查 Linux mountinfo（包含同设备
bind mount）以及同用户全部进程的 cwd/open-fd，包含重命名后路径和 deleted fd。
仍有引用或探测不完整时保守保留，并在终端明确说明。这个检查不跟踪仅保存在进程内存
里的路径字符串，也不防御特权进程或同用户恶意绕过私有目录/锁协议的行为。
命中自身进程引用时，先让 Python GC 释放不可达的循环对象（如未显式关闭的 SQLite
上下文），再执行完全相同的引用检查；仍可达的文件句柄、自身 cwd 或其他进程引用不会忽略。

活跃或无法可靠判断的现场不计为可安全删除对象，可以暂时超过保留数量/时间；
空间预检仍会阻断低空间下的新测试。文件系统删除错误会使会话非零退出，停止继续产生
副本，并保留错误摘要；不会把清理失败报告为通过。不可读目录不会被递归粗暴改权限。

本插件适用于仓库的 Linux/WSL pytest 8–9 环境，不引入新依赖。
pytest-xdist 的 worker 生命周期尚未支持；请求 `-n` 会明确拒绝，不能静默与普通进程
并发混用。绕过根 conftest（如 `--noconftest`）或直接操作 pytest 私有工厂属性不在此契约内。

## 宿主与 Linux 空间

默认 Linux 测试卷和 WSL 宿主卷各要求至少 **5 GiB** 可用空间，与现有资源管理的
最低余量一致。这是停止线，不是测试最大写入量保证，也不是磁盘配额；开始前探测一次，
没有磁盘填充实验，不会自动清理别的项目来凑空间。

WSL 通过当前发行版注册项的 BasePath 识别 VHD 所在卷，并用 PowerShell `Get-PSDrive`
分别探测该卷、Windows 系统卷和临时目录卷。注册表不可读、未匹配到发行版、未知格式、
BasePath、`ext4.vhdx` 叶文件或 Windows TEMP 经过 reparse point/junction、PowerShell 超时或无效输出
都会明确阻断。非标准 VHD 文件名也需独立核实后显式指定实际卷。
Linux 虚拟磁盘剩余容量不能替代宿主实际卷剩余容量。

当自动发现不可用时，先独立核实 VHD 的**实际**所在卷，再显式指定，例如：

```bash
.conda-env/bin/python -m pytest tests/test_pytest_cleanup.py \
  --aa2-host-drives=C,D
```

上面的盘符仅为例子，插件不硬编码本机卷；系统和临时卷仍自动加入检查。
显式卷必须包含 VHD 的实际底层卷，由操作者核实；插件不能从盘符列表反向证明 VHD 位置。
如宿主临时目录本身是重解析目录，自动发现会拒绝，也需将其实际底层卷纳入显式列表。

针对已知小范围、无下载/安装的回归，可以显式设置 `--aa2-min-guest-gib` 与
`--aa2-min-host-gib`，必须为正且有限；先记录用例范围、预计最大写入、实际余量及选择依据。
覆盖值写入每次结果摘要。不要为了运行未知规模或完整套件而随意降低门槛。

## 显式保留全部测试现场

针对不能完整核验进程/挂载引用、但仍需要运行有界行为检查的场景，可显式使用
--aa2-temp-retain-all，例如对当前 checkout 中存在的定向测试文件运行
.conda-env/bin/python -m pytest tests/test_state_format9.py --aa2-temp-retain-all。

这不是清理权限或引用检查的豁免。普通模式及其 fail-closed 检查完全不变；
保留模式根本不请求删除、不执行进程/挂载引用探测，也不清理旧模式的历史现场。
仍执行相同的 Linux/WSL 宿主空间预检。

- 新模式每次原子创建独立的 aa2-pytest-retained-<uid>-<仓库摘要>-<uuid> 容器。
  指定 --basetemp 时必须是从未存在的路径，连已有空目录也拒绝；不重用旧容器。
  父目录不穿符号链接，所有权/0700/目录身份检查仍生效。不 chmod 既有对象。
  新容器创建前仅沿无符号链接的祖先链只读核对 store.json，拒绝位于普通可回收 aa2
  容器内（包括其他仓库），避免以后被外层默认回收。已确认全保留的祖先可嵌套；
  祖先标记无法安全判读时停止，不读取其 run、payload 或报告，不改其内容。
- 容器持久标记 retention_mode=all，与普通模式身份不同。以后普通模式甚至旧版插件
  也会拒绝认领此容器。保留模式不执行启动、逐例、结束、历史现场或报告的轮换，
  不注册这些目录的 atexit 清理。--aa2-temp-keep / --aa2-temp-days 在此模式不适用，
  报告中为 null；它们不会成为自动回收保留现场的倒计时。
- 保留成功、失败、setup/teardown 错误、收集失败、取消、中断和异常现场。
  正常结束的总状态为 retained，测试退出码另列 tests_exitstatus。
  test_outcome=passed 和进程退出码 0 只表示本次行为检查通过，不表示清理通过。
  cleanup.status=not_attempted、process_mount_references=not_checked 和 safe_to_delete=null
  明确保留未做/未核验状态，不能据此声称目录可安全删除。
- 正常配置收尾若没有结束报告，尽力记录 retained_unfinished，不编造测试退出码。
  硬退出可能只留下 running、最后用例和部分元数据；这是未完成观察，不能当通过。
  启动预检或部分创建失败时也不删除已创建目录，诊断列出本次容器和未核验残留；
  可能没有 run/report，容器标记仍说明清理责任。元数据写入故障保留不完整证据，
  不通过删除或改权限来修复。
- 清单列出确切 store/run/work 路径，覆盖整个容器内的载荷。最多另记 128 个工厂分配的
  相对目录名及未列出的分配数量。这不是递归全树清单，不读取任意载荷来测量大小；
  size_bytes=null、size_status=not_measured 表示总大小未知，而非 0。
  现场没有数量或天数上限，可能持续占用磁盘；操作者负责另行核验并取得适用授权后清理。
- 与普通模式相同，已知 run.json 和独立结果 JSON 采用原子替换更新当前检查点，
  不是保存每一个检查点的历史版本。不会改动旧运行或旧失败报告。
- 标准公开 tmp_path、tmpdir、tmp_path_factory、tmpdir_factory 都保留。
  工厂仍使用递增数字目录名，但不创建/替换 *current 符号链接。
  内建 tmpdir 插件和全部原钩子保持加载；其未使用的私有工厂没有 basetemp 引用，
  因此不会执行自身的启动删除、结束 dead-symlink 清理或 numbered-dir atexit 清理。
  此承诺限定于 aa2/pytest 管理的清理，不涵盖被测代码自行删除或第三方插件直接
  操作 pytest 私有工厂属性。绕过根 conftest 仍不在契约内。

本模式的定向验收使用真实根 conftest 与全部原钩子，同时用失败哨兵确认公开路径
没有进入删除或引用探测入口。普通模式的成功删除路径未因此重新执行；
原有中断/拒绝报告保持原样，不能被新模式的行为通过覆盖或改写为通过。
