## 有限范围

- 本轮确定覆盖任务环境管理器的两个既有 npm 入口：初始锁生成 `npm install --package-lock-only --ignore-scripts` 和已声明锁安装 `npm ci`。这两条共用 `_npm_command` 的受控debug归档和运行时身份。
- 不扩大到任意 shell、npm run、npx、浏览器下载、发布后交付、无任务来源的命令；Conda/pip 的未知失败仍保留其既有边界，本轮没有其同场景归档依据。
- 不把错误文本匹配当依赖修改许可；classification 继续是 unknown。也不新增采集执行器、DSL、模型配置、重试额度或权限。
- 已识别的依赖故障与有限传输重试保持现状。产品根因与合法候选仍由 aa2 正常责任阶段判断。

## 准入事实

准入只读取控制器已持久化的外部观察，不采信模型自报或任意文件路径：

1. 当前run/有效计划/任务及版本、候选工作区和 source_hash、base 和 controller_task 的绑定一致；候选未验收且仍为保留的已应用/测试状态。
2. 确为完整采集的非零退出、unknown 归类、有效 npm runtime_identity。argv 只能是上述两个精确形状，npm来自本项目环境目录；cwd只能是该候选已选Node根或控制器临时resolve子目录。验证当前公开 package.json 及必要lock存在、属于接受计划的路径范围，不能使用外部/链接清单。
3. 命令流和 npm debug 引用的原件存在，字节数/摘要/种类匹配；仅读取受控artifact对象并限制总量。缺失、损坏、不完整、身份陈旧或范围不明不得转换。
4. 明确认证、权限、证书/TLS、完整性、磁盘/只读文件系统等失败信号继续人工前提。有限机器码/错误签名是保守排除，不声称能理解所有自然语言或证明未知原因安全。
5. 当前问题若已被回答、已有真实用户前提或另一个不兼容恢复占用，不能把它当未答技术等待自动转换。无法满足准入时继续原等待或受控冲突，绝不自动批准。

现有观察已经带受控argv/runtime/cwd、两份流、debug及完整任务身份；复用这些字段，不为了准入改写历史观察或补造已清理的暂存manifest。原始复制机制的字节身份校验仍是生产前提；准入不是重现完整npm内部依赖图。

## 原子转换与中断

准备阶段只读核验原问题、队列、计划、候选、旧repair/recheck许可、计数和日志。构建相同任务环境失败记录，标注本次只授予只读诊断准入；保持classification unknown。复用 task_outcome_updates 构造上一动作的真实失败结果，不重放候选写入。

一个 CAS 事务同时：
- 保存失败候选及真实失败观察，建立唯一 recovery/active 与对应 failure/history/count；
- 关闭上一已分派动作的对应任务结果，保留其它任务结果；
- 移除这一项等待指针/队列，精确将这一未答问题标为 superseded，answer 仍为 null；
- 写入版本化转换回执（原观察/问题/来源身份/新的恢复身份），不删除原问题、归档、批准、候选或旧许可。

事务前中断没有转换；事务后中断恢复只消费同一回执/active，不重复安装、不增加第二次失败或诊断次数。CAS 同时校验答案与计划/源码记录，用户回答或陈旧绑定赢得保护。原先 prerequisite 回答次数不增加；诊断累计由现有实际执行入口增加；无进展basis仍由真实事实计算，不用新回执文字伪造进展。
