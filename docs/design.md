# auto-agents-2 设计与实施规范

## 目标与边界

aa2 是以持久化状态、版本化工程产物和可执行验收为基础的软件开发编排器。首期支持 Linux/WSL2、Python、React 和 Next.js，使用 Codex CLI 和 Antigravity CLI。交付到本地 Git，不自动推送和部署，不自动更换模型，不引入 Jev，不要求 Docker。

新项目、既有项目和后续迭代使用同一流程。Python 默认 FastAPI，React 默认 Vite/TypeScript，Next.js 默认 App Router/TypeScript；既有工程的框架和行为保持为基线。

## 迭代与需求

`run --requirements SOURCE` 表示新迭代；`run` 不带需求参数默认表示续跑。显式新建时若上一轮未完成则直接报错，提示正确续跑命令，不读取新需求、不启动模型、不更新 provider，也不排队。没有 `--new`。

交互终端的不带需求参数的 `run` 若启动时当前迭代为 `SUCCEEDED`（包括 `NO_CHANGES`），先显示结果、用量和运行指引，再询问是否开始新迭代。选择 y 后使用现有多行编辑器输入需求，Ctrl+D 提交；非空且 UTF-8 内容不超过 4 MiB 才接入。需求模块在控制器锁内将原文原子保存至 `.aa2/requirements/` 的唯一文件，随后复用文件采集、指纹、覆盖评估、多轮澄清和开发流程；文件及原始需求产物持久保留，恢复不依赖临时文件。新建前在锁内重新检查未完成迭代，竞争失败不附着到另一轮。内部 `requirements_text` 参数与来源文件和恢复 ID 互斥，不增加 CLI 参数或数据库版本。

新建提示由 CLI 在渲染结束后显示，不写入已完成迭代的问题队列。选择 n、提交前 Ctrl+C 或输入流关闭均直接退出，不创建迭代、不声称已保存检查点。提交后的中断复用原有暂停与恢复机制。一次命令最多询问新建一次，本次新迭代完成后正常退出；启动时仍在执行的迭代、显式 `--requirements`、`resume`、无历史迭代、已取消迭代和非交互终端保持原有行为。

原始需求可以只有一个想法。保存原始内容、来源和指纹，澄清后生成具有稳定需求 ID 的开发规格、验收条件和决策记录。已确定的规格供所有后续阶段使用，修订产生新版本。

新迭代先做覆盖评估。对比原始请求、已有规格、实际选定基线、测试和验证证据，分类为已满足、实际变化、回归和未知。原文相同不等于已实现，表述变化不等于新增功能。

- 全部满足：返回 `NO_CHANGES`，保存评估证据，不生成实施任务或空提交。
- 部分满足：只规划变化、缺失或回归部分。
- 证据不足：先检查或澄清，不能直接重复实现。

指纹快速路径要求原始需求、当前源码及依赖声明匹配已验证版本，且无需要重新验证的外部服务依据。已有实现仅在其他分支时不能误报目标分支已经满足。NO_CHANGES 也必须完成主目录环境交接与回执；源码和锁文件无变化时不新增提交。缺失依赖锁属于需复测审查的工程差异，不重新开发已满足功能。

## Provider 和 Prompt

配置层次为阶段 → efforts level → active provider 实例 → profile_map → 原生 profile 或统一 JSON profile。level 可以自定义。多个实例可使用相同 kind、不同配置目录和账号。

支持环境变量及 argv 数组 extra_args；null 移除继承变量。模型与推理参数属于用户配置。aa2 不做自动追新，模型 prompt profile 的自动识别只调整文本表达。

切换只能发生在配置实例集合中，成功后保存 active provider。已经派发的调用保持原配置；后续调用采用新配置。成功故障切换不自动跳回旧 provider。用量保留所有失败调用。

Prompt 分为通用任务语义、阶段角色、模型适配、工具调用适配。参考 GPT-6、Gemini、Claude 官方指导，版本化维护并回归测试。模型不得通过原始文档、AGENTS.md 或自评扩大硬权限。

独立审查默认使用当前 provider 新会话，直接读取规格、代码差异和证据；不继承实现会话。跨模型复审是后续可选能力。

设计独立评审绑定当前全部公开架构 Markdown 的内容哈希、规格身份和原始审查产物，向规划及任务审查提供 `design_review` 凭据。同内容经 Git 工作区交接引起的普通读写权限差异不改变文档版本；文件应用恢复仍核对原始模式。回退归档中的原始决定仅在文件哈希、保存的决定及实际产物相符时作为历史证据提供，不代替新规格的当前设计门禁。任务派发和验收前重新核验有效设计凭据。

设计候选提出问题时，控制器先提供匹配的原始设计评审以及公开源码历史，由设计阶段以仅含问题和摘要的结构重新核对一次。该步骤不改动候选文档、文件变更或验收义务；内部评审、报告和历史源码请求由控制器提供，真正的产品选择仍交用户。无现有设计决定时，提交既有候选后执行正常独立评审，不将“先提供评审才能提交设计”交给用户。原问题、响应及候选持久保留；替换候选和撤销旧待答问题使用同一事务，并发人工回答优先，中断后复用已保存响应。

`SourceHistory` 从控制器记录的迭代基线、回退、任务基线及计划修订快照中读取公开源码，为受保护测试及任务范围生成完整的原始文件和差异产物，并绑定 Git 提交及当前源码身份。任务、最终、无改动及重集成审查均可读取相应历史；最终审查缓存还绑定设计评审和历史证据。集成级审查通过同一计划历史入口选择全部任务允许路径的并集，分别使用当前已批准计划、复用来源计划或交付 journal 绑定计划；不能退回仅包含默认受保护文件的历史范围而丢失任务已提供的配置或辅助正文。无计划时仍只选择默认受保护文件。该并集只用于读取历史，沿用敏感路径、普通 UTF-8 文件、内容哈希和提交绑定限制，不改变任何任务写权限；不沿模型引用、提案或任意旧计划推断额外范围。已有范围绑定缓存与冻结材料保持原样，新范围生成新身份；缺失、范围外或不支持的材料仍明确保留缺口，独立审查与所有检查义务不变。当前模型 Git 视图仍只包含过滤后的当前快照，历史比较通过只读产物提供。历史文件同样按 `sensitive_paths`、秘密路径和文件类型准入，不挂载原生 Git 历史或配置；缺失快照明确标记。历史清单还从门禁回退、计划版本和依赖基线更新的控制器归档中读取任务提案，按同一公开路径规则提供原始变更正文、来源、记录的源码身份及历史检查合同/观察；未应用或被拒的提案不能靠 Git 快照恢复，提案正文必须单独保留可读。提案明确标记为建议，历史检查不证明该提案通过，重新提交仍需保护文件审查和新鲜验证。普通任务重试还从同一 run 的 artifact.created / implement / develop/task/<id> 明确响应事件读取不可变候选，避免当前任务槽覆盖后失去未应用提案。核对类型、哈希、长度和结构，按现有公开路径规则只提供变更正文；来源保留事件位置和响应身份，不挂载原始未过滤响应、不沿模型引用递归读取。相同任务与正文去重；返回事件不推断应用状态、源码身份、验收或历史检查，提案断言本身也不能新增批准合同义务。既有门禁、计划和基线归档保持原语义。任务及交付恢复诊断使用同一历史清单。v3 清单对每个已解析快照提供提交和根 tree 绑定的全部公开 Git 路径、对象类型、模式及对象标识；路径清单不按任务范围过滤，正文仍仅提供原有受保护文件及任务范围内的 UTF-8 普通文件。条目区分 included、outside_scope、non_utf8 和 unsupported_type，未提供正文不等于路径不存在；不读取范围外正文或跟随符号链接、子模块。private_paths_omitted 明确是否有非公开路径被省略，只有未省略时路径清单才覆盖整棵已跟踪树；missing 仅表示未解析的历史锚点。Git 树不证明未跟踪文件、外部配置或已安装插件不存在，当前正文比较也不作为完整路径清单。证据读取不增加写权限，所需正文不可用仍保持证据缺口。缓存版本升级只影响新收集，已有冻结调用和历史产物保持原样。仅显式选择的历史清单展开其源码、差异及提案附件，源码和提案正文中的引用不能扩大材料准入。差异与当前测试通过均不等于测试修改已获独立批准。

历史范围入口必须显式选择：任务使用当前绑定 TaskSpec，计划使用当前／继承／交付 journal 绑定的 PlanResult，诊断与修订共用计划任务子集选择。省略范围、缺失计划或未知任务不能静默退回空范围；确实无计划的设计核对、复用或诊断分支明确选择受保护文件。既有清单 v4、冻结输入、来源权威与恢复进展身份保持不变。详细边界、调用图及真实工作流验证见 [P0 证据交接设计](evidence-handoff-design.md)。

### 按阶段选择模型输入

`ContextPlanner` 在 provider 挂载材料和编译 prompt 前按阶段及用途生成 `PreparedContext`；正常流程、各类审查、补丁纠错、恢复、决策、doctor 和读取探针均有显式契约。未登记用途拒绝派发。控制器保留完整原始事实，模型使用独立的输入视图；已知无关字段不选入，尚未分类的扩展约束保守保留并记录原因。64,000 字符是首包与 schema 的软目标，不能用截断必需约束或证据来达标。

澄清提供本轮原文、当前问答、基线和历史需求索引；可证明不在当前基线祖先上的历史不选入，未知关系明确标注。研究提供当前声明、版本、相关章节及补读入口。原型提供受影响界面、设计和真实浏览器证据；设计目录按固定版本索引读取。设计与规划提供当前规格、接口、设计、审批及任务血缘。实现和任务审查提供任务、关联需求、共享约束、有效检查契约、相关代码和未解决问题。需求只有在当前已接受计划明确归属其他任务时才可从任务视图排除；未归属和旧记录中的约束保留。README 仅需当前行为、文档和运行契约。最终、无改动及重集成验收保留全部适用义务、当前检查和视觉证据。恢复、决策和计划修订提供当前故障、允许动作、相关完整任务及全局依赖图、历史动作结果、累计消耗和发布状态。替换纠错只展开目标文件此前替换和失败项。辅助探针不携带业务开发规则。

短的必要正文保持内联，避免为了减少字符增加无必要的模型补读轮次。大正文按内容身份归档，通过只读引用提供；模型须读取标记为必读的约束，并按需要读取相关支持材料。源码按目标路径、失败位置、直接项目依赖、入口和配置选择，适用 AGENTS.md 完整保留；完整公开源码仍可搜索，读取范围不扩大写入范围。测试视图保留每条检查的状态、有效性、退出码、计数、失败原因及未通过用例；日志、完整报告、通过用例明细及历史观察提供可核验引用。当前证据与旧反馈分开，不能以旧故障覆盖当前检查。

研究原始响应和完整提取正文继续保留，章节索引绑定正文 hash 与字符范围。标题锚点覆盖到下一同级或更高级标题，容器锚点覆盖完整容器。短的直接链接定义在完整保留且不超章节内联额度时一并提供，其他定义可经索引补读；不同版本与声明不合并。缺失、重复锚点和无锚点长文提供定位状态、索引和全文入口，不伪造摘录或默认塞入全文。

材料挂载按当前选择清单进行，不沿所有归档边自动递归暴露。选中结构化证据的报告、日志和截图依赖仍有明确入口，已正常释放的日志标记不可用；意外缺失或损坏仍阻止调用。过滤列表保留原索引或稳定标识，派生材料引用映射回原始控制器路径；同内容多来源时不能用歧义 hash 代替精确引用。呈现、原生会话版本与逻辑调用身份分离，旧已完成响应、原始授权及计数保留。新视图在派发前冻结并按相同序列化顺序恢复；所需产物随调用和未完成工作受保护，完成后沿既有生命周期回收。

材料清单记录选择原因、来源身份、实际正文/规则/schema 字符数、补读材料大小和超目标原因。字符数、可读附件字节数与实际 provider token 分开报告；能力探针、失败及重新对照的用量不隐去。真实对照同时检查正确性和累计调用输入，不能把 stdin 变短视为总用量下降。

恢复故障只持久登记显式证据别名和公开源码路径；字段路径、数组索引及产物 hash 的完整引用目录在校验时派生，不复制到每个候选动作及历史许可。`context-v2` 按列表的总大小处理旧的大引用目录，提供带内容身份的按需入口；目录是定位元数据，不是必须逐项阅读的新证据。历史逐用例进度保留真实计数和完整账本入口，历史观察按需读取，当前检查状态、未通过用例、审查缺项、任务范围、验收义务和累计消耗仍完整提供。标量观察次数不能误作历史正文归档；选中记录的日志和报告依赖只挂载一次。原始记录及引用校验的事实／提案区分保持不变。

`context-v3` maps selected dependencies of directly supplied artifacts back to their original controller paths, as it does for compacted records. The same attachment reached from different origins remains ambiguous unless it is also directly supplied. Proposal origins stay unverified; source/proposal contents do not mint citations or expand admission. Pending v1/v2 presentations upgrade without replacing their old records, completed responses, authorization or counters.

`context-v4` 在公共检查视图中只展开一次内容完全相同的观察；每个问题的状态、归属、失败用例及原始引用位置仍独立保留，重复位置指向首份视图并附带完整观察的只读引用。仅内容摘要完全一致才复用，源码、环境、命令、结果或附件变化均形成不同观察。大型检查附件目录提供完整的按需索引，附件内容继续沿既有证据依赖规则挂载和校验；缺失、损坏及来源歧义不因精简而变成成功。大量依赖位置条目在校验后组成完整只读索引，首包保留索引入口；挂载清单仍逐项验证并实际挂载，显式输入文件保留可见，已在材料中给出的地址不再另复制一遍。索引只用于定位，不增加可引用事实或权限。此变化只优化呈现，不改变账本、验收合同、授权或资源保留规则。未完成 v1/v2/v3 呈现另存新版，原始记录及已完成响应不被替换。

`context-v5` 区分原始控制器引用和呈现别名：原始上下文引用目录已登记的真实产物 hash 即使随大型附件目录折叠，仍保留原始身份，不因多处引用而被新呈现别名遮蔽。未直接提供的依赖仍映射到原始来源；真正多来源歧义仍拒绝，提案正文不能因此获得控制器事实权限。该规则使用同一原始引用目录，不新增事实、批准或验收义务。未完成 v4 视图与更早版本一样另存新版，旧响应、许可和累计次数保留；损坏和未知视图版本继续拒绝。

旧版未完成调用可从原始冻结输入生成新版呈现，另存版本化检查点并保留旧呈现；新版首次派发与恢复使用同一序列化结果，损坏或未知版本不能静默替换。呈现版本隔离原生会话，不改变逻辑调用、授权或预算身份；已完成的决策（包括 `ask_user`）和诊断不因输入优化重跑。整份 prompt 的文件传输只解决 CLI 入口长度限制，不能充当上下文选择或减少实际必读内容的方案。

## 工作流与门禁

1. 接入项目，检查环境、Git 和既有测试，建立安全基线。
2. 保存需求快照，覆盖评估，对话澄清和独立需求检查。
3. 研究外部服务一手资料，标明版本和实际验证程度。
4. 有 UI 变化时生成静态交互原型。新设计参考 VoltAgent/awesome-design-md，固定来源版本。
5. 自动浏览器与独立审查通过后等待人工原型审批。
6. 设计模块、接口、数据约束、事务、迁移和验证策略。
7. 生成覆盖未满足需求的任务 DAG 并独立审查。
8. 逐任务实现、针对性测试、独立审查，受控集成。
9. 完整验收、前端对照、文档更新和本地 Git 交付。

原型审批绑定内容及动作契约；检查器版本单独管理。迭代只改变相关页面和组件，公共样式变化触发相关回归。审批前本轮后续阶段暂停，但进程和预览服务保持可用。

人工批准必须追溯到未作废的 `prototype-approval` 问题及明确的批准答案，独立审查通过或任务已派发不能替代该记录。控制器在缓存恢复、任务派发、最终验收、无改动交付及重集成时统一核验内容、动作与原始审批来源；向实现和审查提供结构化审批凭据。生成时文档中的“待批准”文字不是实时门禁状态，不为修改该文字而改动已批准的设计。旧内容指纹仅在原型未变、原报告完整覆盖当前动作且原始人工决定可核验时迁移；自动证据按当前检查器重新采集并独立审查。旧任务因缺少审批上下文提出回退时，先保存原请求，在核验真实批准后允许带完整旧请求重新判断一次，保留已验收任务、轮数、回退历史和恢复产物；已收到审批凭据后再次提出的回退正常处理。

原型浏览器动作的路由相对于 `design/prototypes`，包含子目录和查询参数。控制器执行每个声明场景，同一路由内按顺序执行动作，不在步骤间重新加载；不同场景和视口隔离浏览器状态。旧候选的根目录文件名仅在可唯一匹配页面时兼容解析，路径缺失或有歧义必须明确失败，不能静默跳过动作。页面加载与截图不等同于交互通过。实际执行报告保留已完成动作、首个失败步骤和错误，跨回退提供给模型；控制器内部证据不应要求用户补交。检查器升级后，旧截图证据重新验证，原候选、报告和提问历史保留。

浏览器检查版本 6 在动作末态先按原视口截图，避开 Chromium 整页采集可能短暂切换到 1×1 视口并触发响应式状态变化的问题。超出视口的内容按滚动位置补充完整视口截图，每张保持原宽高、不裁剪或拼接；报告记录原滚动位置、视口高度及各补充图片的位置。补充采集前后复核末尾连续断言，页面尺寸变化或无法完整覆盖时失败，结束恢复原滚动位置。所有图片独立归档和验证，原型及应用预览共用此规则。

`frontend` 表示目标包含前端，`ui_changes` 表示本轮是否改变界面。界面未变且内容指纹完全匹配时复用之前的原型审批，最终应用浏览器验证仍然执行。设计目录使用 Git 提交指纹，避免匿名 API 限额影响新项目初始化。

任务包含需求 ID、允许路径、依赖、验收方式和实际检查命令。共享文件冲突的任务串行。首期最多两个开发工作区和一个集成工作区。

## 文件修改与测试保护

Provider 在只读视图中检查项目，返回结构化文件变更。控制器先验证所有路径及范围，再将候选写入工作区。替换操作记录前后内容指纹，以便部分应用中断后的幂等恢复。

同一文件可包含多处 `replace`，按候选列表顺序在内存中执行，每一步的 `old_text` 必须在此前替换后的内容中唯一匹配。控制器将其合并为该文件的一个原始/最终指纹对，整批校验通过后再写入；同一路径的重复 `write`、`delete` 或混合操作仍拒绝，不能以后一项覆盖前一项。

原型、文档、任务实现及交付修复共用 `PatchRepairService` 处理 `ReplacementMismatch`。校验器报告失败项序号、路径、匹配次数和原因；控制器归档原始候选，按公开材料路径准入提供当前文件，让原阶段、原用户 profile 的新会话修正该项的 `old_text/content`。仅该项文本可变，路径、操作类型、其它修改、文档元数据、验收及审批契约保持不变。扩展匹配上下文时必须在替换内容中保留周围代码；不能用模糊匹配、自动忽略空格或跳过替换代替校验。每次响应后重新按顺序校验整批补丁，全部通过后才进入原有应用、测试保护审查及验收流程。

每份逻辑候选最多两次自动补丁纠错，预约请求、原候选、各次响应和已用次数持久化。相同候选重启或重复确认不重置次数；保存响应后中断复用该响应，不重复调用模型，也不增加业务实现轮数。两次仍失败或 provider 响应失败时保留现场并明确报告原因。显式上游重规划产生新的候选身份，旧记录保留。缺失文件、非公开文件、越界路径和其它策略错误不通过此通道扩大权限；纠错期间源码漂移阻止旧响应应用。已有 prepared 补丁及部分应用恢复继续使用原始前后映像，不重新生成补丁。模型修正成功不代表测试、独立审查或人工审批通过。

开发可以提供新测试及现有测试候选修改，受保护测试、fixture、脚本和截图基线的变化必须经过独立审查。实现者不能直接改正式验收数据或 controller 状态。

检查由 VerificationService 运行，并绑定源码、环境和实际退出结果。针对性测试与最终验收分层，避免每个小任务都重复完整 E2E。pytest 使用独立保存的 JUnit 用例与通过数量作为证据。候选代码、环境、规格或检查命令改变后相应证据失效。

`Command.outputs` 声明工作区相对的构建输出目录，消费者在 `inputs` 声明所需产物。控制器按生产者依赖排序；任务只执行它实际依赖的 `runtime_prepare`，最终验收在所有检查前完成运行准备。生成目录不随 Git 任务集成传递，必须在消费它的实际工作区重新构建。旧 Vite/Next 的 `npm run build` 可依据项目依赖识别标准 `dist`/`.next` 输出；不同生产者冲突、循环依赖和输入输出重叠在启动前拒绝。同一构建的重复声明合并输入、保留较强的测试数量和已声明的较长超时。

输出声明不能扩大写权限：仅允许命令 cwd 的 `dist`、`.next`，拒绝符号链接及包含已跟踪源码的目录。构建在空的隔离输出目录运行，成功并校验产物后才发布；失败不消费旧产物，发布失败恢复原目录。`CheckResult.generated_outputs` 保存产物指纹，丢失或篡改即使源码未变也使证据失效。Next 的运行缓存和 trace 不作为不可变构建内容；执行源码与构建清单仍校验。缓存复用、审查结束、最终浏览器验收及运行交接均复核输入和输出。最终预览以只读方式挂载完整候选工作区，使后端可读取前端产物；本机检查显式绕过代理，保留外部代理配置。

verification-v11 统一显式 inputs 与自动 Node 依赖采集：已识别 node_modules 根目录下的运行缓存不进入依赖指纹，声明父目录或别名时也采用同一规则。包内其它同名目录仍纳入指纹；直接声明的缓存文件仍按其内容校验，构建产物不使用 Node 依赖缓存排除规则。后续检查写入运行缓存不能使先前已通过的检查失效。旧校验器的结果作为历史证据归档，保留当前候选并按新规则复验，不改写旧结果的版本或重置实现次数。

Provider 源码视图不挂载真实执行工作区，并按公共路径规则排除 dist、.next、依赖与缓存目录；`project.view_contract` 明确该边界。日志中的执行绝对路径仅提供来源，不能据模型沙箱中路径不可见认定宿主产物丢失。任务、最终及无改动复用审核仅在现有确定性证据校验成功后收到 `verification_observation`：绑定源码、环境、完整命令/检查摘要及实际产物指纹。该记录只陈述门禁入口时的验证观察，不授予权限、不替代独立语义审查或必需的浏览器/产物正文证据，也不作为可复用许可；审核后继续重新核验实际输入和产物，缺失、篡改或过期仍拒绝。公共视图和提示版本升级保留旧记录，不为旧审核补写新观察。

任务调用独立审查前及批准后均核对完整验证证据。源码未变而依赖、产物或其它验证身份失效时，保存候选和审查记录，将具体验证错误交现有证据恢复流程复验；不能把无效证据送入审查或当作新的实现缺陷。已记录源码指纹发生变化时仍保留现场，阻止自动覆盖。失效原因标明对应命令及输入、环境、策略或产物，避免一律归因为构建文件在审查期间改变。

检查命令按解释器选项解析，识别 `python -B/-I/-W/-X ... -m pytest`、版本化 Python 和直接 pytest。Vitest 与 Playwright 支持直接命令及简单 npm scripts，报告写入控制器独占临时目录并归档；未知包装器不能用 stdout 数量代替报告。空、损坏、计数不一致、全部跳过及套件级错误均不能通过。`process_exit_code` 保留原始进程状态，`exit_code` 表示验收结果，`failure_reasons` 区分报告缺失、测试失败、超时、输入变化等原因。检查器版本变化要求重采证据。

命令组装属于检查器契约：同时检查原 argv 与 npm script 的已声明参数，保留测试文件、过滤表达式、npm 前后置脚本及环境、cwd、timeout、expected_tests 和 inputs。运行模式与报告参数按各工具的单值/多值规则合成，重复组装保持幂等；npm 的转发分隔符和 runner 的参数结束分隔符分别处理。报告路径归控制器管理，已有普通报告文件不得覆盖。显式 watch、禁用报告插件、无法安全覆盖的 npm script 内固定 Vitest 报告路径等冲突在启动前明确报错，保留已应用候选，不进入源码修正循环。

参数化用例允许同名，但报告必须提供一致的测试总数。重名组以名称、组大小和组内序号绑定身份；实际通过数量按真实报告行计算，进展比较仅在该组全部通过时记通过，重排或改变组大小不能伪造单个用例的改善。没有计数约束的重复记录仍拒绝。

旧检查器参数组装或报告采集导致的任务回退，先核对原任务响应与未改变的候选，再采集原验收命令的当前证据。兼容入口仅负责证据恢复，未解决的检查进入统一裁决。原始证据、回退、未应用提案和轮数历史保留；原任务仍需通过所有检查及独立审查。新的任务反馈使用当前检查，历史故障保留在归档中，不能重新作为当前结论。

旧版遗漏构建前置的回退，从已接受的计划解析前置构建，在原候选上重新执行检查。构建退出成功且产物可核验时，构建问题已解决；其余断言仍失败时分别保留，不能要求整个项目全绿才能关闭原构建问题。实现与审查收到版本化 `verification_contract`，其中列出控制器的实际执行顺序；旧计划正文不能覆盖该执行契约。已收到新版契约后再次提出的回退进入统一故障裁决。

verification-v6 同时识别 Node 显式执行的项目包入口：`node_modules/vitest/vitest.mjs`、`node_modules/@playwright/test/cli.js` 和 `node_modules/playwright/cli.js`。报告参数只追加到测试运行器参数段，保留解释器选项、测试选择与配置；任意 JS 文件、`node -e` 和仅在参数里出现的运行器名称不被误认。`unsupported_test_runner` 属于证据采集故障，先重新采集，不能据此消耗下一轮业务实现。诊断的引用目录由控制器提供的检查记录、日志哈希和公开源码路径生成，模型自行声明的引用不自动取得可信身份；无效诊断会在同一故障预算内反馈修正。

## 恢复与有界循环

Provider cancellation accounting distinguishes a confirmed pause from an unknown request. Only an observed cancellation of a still-running managed process, successful cleanup and usage persistence, and absence of a response or known error produce a cancellation receipt. The same logical input may consume one such receipt per operation/provider to resume on a later invocation; cancellation itself always propagates and never loops into a retry. Further cancellations, a crash/legacy pending checkpoint, changed input, unconfirmed cleanup or a response of uncertain status retain budget occupancy. Failure, cancellation, resumption, grant and token history are not reset. Decision response/correction limits and committed-result reuse remain unchanged. Saved manual fallbacks and unanswered questions are not migrated or revoked by this policy.

设计阶段通过 `DesignDocuments` 落盘并独立审查架构文档，再进入规划。`DocumentResult.document` 默认生成 `docs/aa2/design.md`；`files` 可修改该入口、`docs/aa2/design-*.md` 及 `docs/aa2/design/` 下的 Markdown。若 `files` 显式修改入口，以实际应用后的文件为准，不能随后用 `document` 覆盖替换结果。设计阶段不能修改产品源码、原型、规格、计划或环境锁定记录。替换锚点不匹配复用有界补丁纠错。

设计提案、文件前后映像、完整输入身份和独立审查存入 `candidate/design`。部分应用恢复按原映像继续；未知源码、文件内容或模式变更阻止自动覆盖。审查失败不进入规划，成功后后续阶段读取最新源码快照。旧版保存了 `design.files` 却没有应用与审查回执的迭代返回设计门禁核对，既有阶段归档机制保留旧提案、任务、预算和原型人工批准。已存在的恢复授权继续按原绑定处理。

规划及局部计划修订拒绝将 `DESIGN.md`、`docs/aa2`、`docs/requirements`、`design/prototypes` 下的契约路径显式分配给实现任务。已接受的架构记录义务保留为对上游产物的核验；不能用删除验收条目、计划附录或扩大实现权限替代缺失设计文件。恢复提示同时显示候选补丁拒绝和恢复提案校验错误，空检查记录不作为产品缺陷的证明。

### 统一故障与恢复契约（状态库 v8）

动作授权统一由 `action_authority.route_action` 按控制器事实、现有许可、自动化配置和动作效果选择规则／决策／人工。阶段名称不构成人工边界：诊断建议返回澄清、研究、原型、设计或 README 时，决策请求明确列出失效阶段、受影响任务及必须保留的义务，再由决策代理评估；控制器已确认的首次契约纠错可直接按规则重做。许可只允许重新进入阶段，不批准该阶段产物。业务问题、原型人审、真实凭据或资源前提、未知用户修改和已发布日志仍按原边界核验；发布后的阶段回退及计划修订不能通过自动许可绕过。

同轮旧人工许可的范围不匹配时，不能沿用该许可，也不据此否决一次新的独立决策。旧未答技术确认在新许可的事务提交时撤销；已有回答、暂停及完成回执保持原义，事实变化或并发回答使旧决策失效。动作分类、实际路由和授权结果分别显示，不把“需决策评估”当作已经运行决策代理。

恢复路由的展示直接依据控制器的 `route` 与 `reason_code`，不另存可被秘密字段脱敏改写的授权布尔副本。历史事件中的 `<redacted>`、字符串和数字不能按真值解释为用户授权；已应用授权标志必须为显式布尔真。已有回答标记为 `recorded_answer` 并先核对其含义，只有已生效且范围匹配的许可才显示复用授权。复用已保存的决策时单独记录 `decision.reused`，说明返回的是历史结论；旧 `ask_user` 的失败理由不表示本次又执行了模型调用。显示事件写入失败不能改变已保存决定、消费许可或触发重试。暂停回答仍只表示暂停，之后的明确批准才形成恢复许可。

覆盖未知或声称已满足但没有可执行检查时，控制器返回澄清阶段检查当前源码及既有测试契约；不会直接要求用户寻找内部代码或填写命令。真正缺失的产品信息仍由澄清交互收集。澄清批次结束或模型漏掉验收条目属于候选纠错，保留反馈后进入恢复评估，不按次数直接报内部错误。原型、设计和文档的候选路径拒绝或替换纠错耗尽返回各自阶段；README 错误不使已验收任务和计划失效，未知工作区改动仍禁止自动覆盖。

`ProposalRecovery` 在正常生成、审查及验收调用的响应格式错误之后，向同一恢复策略申请一次只读重新生成。请求绑定原任务、schema、源码及逻辑操作；每次失败与许可持久记录，累计次数和 token 不清零，响应格式通过也不代表任何验收通过。provider 切换后仍保留错误类型；已记录的同输入格式失败在重启时直接复用，不能误报为认证故障或占用新的调用。决策、独立诊断及补丁纠错保留各自现有纠错契约，禁止决策代理递归批准自己。成功迭代按既有资源流程回收临时呈现与响应恢复正文，历史计数和许可保留。

响应纠错使用独立尝试键，但问题范围、产物逻辑操作和 `invocation/<原操作>` 仍归属原门禁；尝试及原操作回执在同一事务保存。普通重启复用已保存结果；明确阶段回退的版本进入响应恢复身份，不能重新取回已被业务审查拒绝的旧候选。

`FailureRecord` v2 保留原故障血缘 ID，增加阶段和持久化观察 ID；实际新执行结果产生新观察，读取、展示和重启不生成新观察。编排、验证、环境、传输和资源组件分别提供故障事实，恢复控制器消费结构化原因，不解析提示文字。检查实际失败和证据不能证明结果分别记录；没有有效用例报告不能证明业务断言失败。

| 故障 | 处理契约 |
| --- | --- |
| 有效检查或独立审查失败 | 独立诊断或已有依据支持的范围内修复；需要权衡时交决策 |
| 报告、验证身份或构建产物失效 | 保存候选和旧证据，复验；重复同输入动作取得新决策 |
| 可识别环境故障 | 单次环境恢复结束后由决策选择下一动作 |
| 诊断或决策协议错误 | 结构化反馈及既定格式纠正；决策不能递归授权自身重试 |
| 状态或源码冲突 | 根据控制器日志协调；无法归因的修改保留现场并核对 |
| 真实审批、资源或外部条件缺失 | `HumanRequirement` 明确原因、所需操作及解除条件；确认不跳过核对 |
| 未识别的程序异常 | 记录内部故障，PAUSED 并以 INTERNAL_ERROR 退出，不创建笼统的 y/n 问题 |

任务、最终、复用、重集成、运行及完成收尾使用同一证据评估接口。评估返回命令、原因码和输入类别；源码未变时只失效受影响检查及依赖其结果的审查，不重复业务实现。发布后的适配器继续使用交付日志及独立预算，不借统一故障分类扩大发布权限。未知异常记录类型、栈位置及故障编号，不保存异常原文、局部变量或 provider 配置；无法写入故障记录时不得提示保存成功。

恢复身份分为血缘／观察、授权动作和模型调用三层。授权动作按源码、计划契约、任务范围和动作效果绑定，展示理由和引用别名不改变动作身份。决策请求冻结原事实快照，自身 token 记账不产生新请求；真实事实或范围变化仍拒绝旧授权。已完成许可和结果不可覆盖，任务结果、复验及计划派发沿用原回执。模型调用的传输／提示版本改变不能重新生成已完成的诊断或决策。

Local plan amendment authors and independent reviewers receive the selected recovery decision, accepted design and scoped SourceHistory together. These inputs freeze under the existing amendment identity before generation and survive interruption unchanged. The review must assess whether structured contracts address the evidenced recovery objective, not merely whether the old contract survives. Historical proposals remain unverified, and plan approval does not accept an implementation or discharge fresh verification obligations.

验证批次按逻辑操作保存 started、completed 或已清理的 interrupted 状态。completed 结果在消费方保存前发生中断也可复用；消费者仍核对当前验证身份。started 且无法核实完成的批次保留占用，不能自动执行第二次。已确认取消清理的批次形成证据恢复请求，由新动作决定是否复验。主目录运行在同一个预约上接续已完成检查，不重复消费运行次数；完成证据真正失效时归档旧回执，并在原发布后预算内预约新检查。

引用校验 v4 使用共同 `ReferenceCatalog`，由生产者标明事实与提案来源，记录所属观察；历史模型诊断仍是提案。保留根名称、点路径、数组索引、已登记哈希和控制器别名，规范化只解析真实存在的引用。引用存在、来源可信和足以支持动作是不同判定；提案不能生成事实 ID、扩大范围或证明验收通过。检查器 v12 保留 v11 精确的运行缓存排除规则，并返回结构化失效原因。

旧运行探针未声明 inputs 时，将当前生成目录 dist、build、.next 及计划声明的构建输出补入编译后的只读输入契约，使用共同的输入指纹和缓存排除规则。复用同一运行预约的已完成结果时，命令契约和环境仍必须匹配；生成内容变化形成证据失效，不重复执行已完成预约或接受旧结果。没有耐久运行预约的独立探针每次创建新观察。

v8 仅由持锁运行入口迁移，先备份，再事务保存原始记录和适配后的活动恢复视图。旧许可与真实回答保持原义；旧引用拒绝仅重验原依据不变时最后一份已保存响应。未答通用 incident 问题只在新许可或明确阻塞记录落盘时替代。旧检查结果归档，由当前验证策略重采；历史实现次数、已验收候选、用户修改和审批不清零。只读 status/logs 不迁移；旧二进制拒绝新状态。

状态和事件在同一事务中保存。等待输入、执行、暂停和完成区别记录。恢复先取得项目锁，核对残留进程和工作区，再接续未完成子步骤。恢复无需再次传入需求文档。

生成及验收阶段每次失败都进入恢复评估。`automation.enabled` 默认 true；控制器规则能确定的动作直接执行，需要权衡或重复尝试时调用决策代理。实现、独立诊断、停滞及局部计划修订的累计次数只记录，不构成停止条件。旧 `execution.max_rounds/max_diagnosis_rounds/max_stalled_rounds/max_stalled_replans` 和 `automation.max_implementation_rounds/max_diagnosis_rounds` 兼容读取但不限制这些阶段的继续执行，包括显式配置值。没有进展或完成一轮恢复均不自动转人工，由决策选择继续、换方法或请求用户。模型调用不设总时长限制；测试、构建与环境命令保留单次超时及传输重试边界。环境单次自动重试结束后，再次准备须形成新的恢复许可，不删除历史计数。

回退比较控制器实际校验的规格/计划契约、绑定源码/环境/检查命令的退出结果与 JUnit 通过用例，以及两种视口实际执行的浏览器断言及其前置步骤。每个验证范围首次观测的验收项固定；改名、追加简单断言、审查措辞变化、文件数量和模型自评不计进展。只有固定验收项新增通过且已通过项没有退步、验收项没有缺失，才清零连续停滞次数。退步再恢复到历史最好结果不重复记功。缺少可比较证据按未证实改进处理，不以模型判断补足。

进展、累计消耗和重复失败历史是决策输入，不能代替任何验收门禁。回退及停滞记录跨进程、任务改名、拆分和 provider 切换保留。环境未准备、候选补丁被拒绝和恢复提案单独记录阶段失败，只有应执行的检查没有有效结果才累计缺证据。工程里程碑按原始任务血缘记录候选补丁成功应用、环境准备成功、构建产物有效和检查证据有效；首次达成记功，退步后恢复不重复记功。诊断成功、授权、修订获批和审查措辞变化不构成工程或业务进展。

进展使用固定命令、JUnit 用例和整体审查门禁，诊断和授权本身不计进展。审查问题的措辞及条数不能证明部分问题关闭。完成一次实现与验证/复验才记录一次观察；同一持久化观察重复恢复不重新计数。回退仅使受影响阶段和证据失效，历史保留。

### 固定任务阶段与受限时序纠错

`task-stages-v1` 将现有执行顺序作为任务规划、计划审查、实现、受保护变更审查、实现验收和恢复角色的共同指令：必要材料/授权、只读候选生成、适用的受保护测试/配置审查、应用、环境准备、检查、验收。候选审查可以要求充分历史材料及候选映射，却不能把自己的通过回执要求在候选生成前提供。实现代理提供候选和映射，独立审查评估内容；诊断和计划批准不产生候选验收回执。真实缺失的材料、用户前置要求和最终独立验收保留。

阶段合同的可引用来源是控制器实际提供的 `controller_stage_contract` 记录，包含生命周期版本、引用协议版本、原文、权威范围和内容摘要。计划修订作者与独立审查共享冻结记录；诊断及恢复决策获得同一协议来源（决策放在 `decision_request.evidence` 内）。共享引用目录仅承认当前完整记录的路径与摘要，未知路径、伪造内容及过期版本仍拒绝。协议引用只支持流程时序解释，必须另引实际项目事实；它不证明材料齐备、用户批准、断言保留、测试通过或实现验收，引用语法目录也不是项目事实。旧归档没有该来源时不补写、不追认旧拒绝。

时序修订日志同时绑定所用阶段合同；未激活日志在合同内容或版本变化后拒绝激活，冻结作者/审查上下文也不得静默升级。计划修订的无进展依据纳入实际提供且可解析的协议记录，因此修复引用供应能力后可走新的正式选择，历史拒绝、累计次数、旧决策和已有人工问题全部保留。新合同下仍按两次相同依据的无效修订停止；仅改提示词、重启或重新授权不能刷新路径。诊断无结论计数不因这项引用能力补齐而重置。

计划作者和审查者负责判断自然语言是否与阶段冲突；控制器不声称理解所有条款。已接受的错误条款必须走既有 `PlanPatch` 流程，不能由实现代理忽略。`timing_corrections` 显式给出任务、旧验收索引和原文、新文、既有下游产出阶段、理由与实际证据引用。控制器只机械核对版本、唯一映射及结构不变量：只修改映射条款和相关描述，其他验收逐项不变；任务 ID/血缘/依赖/范围/命令/用例门槛及环境、运行和最终合同完整相同，不混入增删任务或其他修订。普通修订仍使用原来的字面义务保留规则。

既有独立计划审查增加逐条时序评估：是否只改时序、是否保留实质义务、是否保留用户要求的顺序，必须给出理由和可解析的控制器证据，不能只引用新提案。任何否定、缺项、额外项或未知引用拒绝激活；肯定判断仍可能有语义错误，后续受保护变更审查、环境证据、实际检查和最终独立验收继续负责各自责任。持久日志绑定旧计划、修订、候选和审查；激活重新验证结构、审查和绑定，沿用既有版本 CAS、源码基线、快照及历史归档。过期修订不可激活。

`RecoveryProgress` 只排除两类已观察到的同依据无效动作：两次通过协议校验的无结论诊断，或两次被拒的时序纠错。诊断格式、引用或范围校验失败使用原来的纠正和恢复授权流程，不按本规则计为有效的无结论诊断。依据包含固定阶段合同版本、原故障身份、适用实际观察、源码及提供给代理的计划/规格/设计/历史材料；不包含调用次数、诊断措辞或修订拒绝文字。操作开始前固定依据，记录按逻辑操作幂等，完成后断点续接不会重复计数或否定已记录结论。已有许可继续按原绑定执行；排除只影响新的动作选择。

动作排除不代表验收通过，也不全局禁止其他修复。决策收到排除原因及保留证据，能选有效替代动作则继续；自动决策无法给出替代时以 `RECOVERY_PATH_EXHAUSTED` 暂停并保留现场。相同事实重启不再次调用模型；真实材料变化可创建不同的选择身份，旧结果不覆盖。已有人工问题不得被此机制替代、授权不得扩大；关闭自动决策和真实前置权限继续使用原有人机边界。普通累计轮次仍只作记录。本机制不判断任意语义相同的失败，也不保证模型不会提出另一种错误计划。

### 故障裁决与局部计划修订

实现模型返回 `recovery_request`，包含原因、建议动作和证据引用；旧 `replan_stage/replan_reason` 作为兼容输入保留原文。模型建议不再直接清除计划或后续阶段。`FailureRecord` 保存产生故障的组件、任务血缘、失败步骤、固定验收义务、原始提案和证据；其身份不依赖模型措辞、任务改名或计划版本。`ExecutionContract` 向实现者提供计划/任务版本、允许路径、真实审批来源和控制器编译后的命令。

规则先处理缺失/无效报告或生成产物：在原消费位置重新准备并复验，不消耗实现轮数。首次确定恢复可直接授权；相同输入再次复验须获得新的有效决策，不因次数直接禁止。未明确归因的故障先独立诊断；有效诊断得到的范围内恢复直接执行，历史停滞不重复拦截。任务及交付诊断使用独立 `recovery_diagnosis` 阶段、新会话和用户 `max` profile，实际模型/effort 仍由用户配置决定。恢复同一已预约调用不重复扣费。诊断必须引用控制器证据，跨任务目标逐项核验路径和范围，每个任务只能有一条 repair_target。一次格式/范围纠正仍无效时，将这次诊断失败交给决策层判断下一步；决策层自身无法给出有效结果才转人工，不能递归批准自身重试。真实原型人审记录仍单独核验。

诊断返回 diagnose 或仅建议 blocked 时，生成及发布前验收先由决策层评估允许的下一步，不能把诊断未定直接转换成人工边界。diagnose 只表示新的只读模型诊断，执行既有检查应选择 recheck；本轮检查记录为空时，仍可选择已接受计划中声明的检查。允许重新诊断必须获得新许可；已完成的诊断响应在重启时复用，不重复计数。附件采集资源限制、真实原型人审及发布后核对仍按各自控制器边界处理。旧 diagnose 被映射为 blocked 产生的未答确认，只在源码、计划、故障及范围不变时重新决策，旧绑定与新的有效许可在同一事务内归档、更新并撤销旧问题；已有人工回答和许可不扩大含义。

诊断输入的 `allowed_actions` 与授权层复用控制器的状态适用性计算：候选阶段、原型批准、当前预览合同及发布状态决定证据补采动作是否可用，模型不能通过建议动作使其满足前置条件。诊断返回后再次校验；不可用动作作为诊断提案错误进入既有纠正流程，不转换成需要用户修复的状态冲突。已完成的旧诊断保持原回执和累计次数，新增适用性拒绝单独归档；已有许可、人工回答和验收义务不因此扩大。`blocked` 仍只是诊断未定的表达，由控制器决定后续路由。

诊断与决策使用同一套证据路径索引规则。诊断可引用实际提供的 failure、plan、current_issues 等控制器上下文中的字段、数组元素和产物 hash；修复路径仍须通过原任务范围校验。提案正文不建立事实引用，未知引用的纠错反馈标明具体数组位置。空的本轮检查记录不代表历史测试通过或失败，也不自动授权执行诊断文字中建议的额外命令、环境变量或未应用补丁。

已完成且已校验的诊断以 ActionPermit.outcome 中的结果为准。续跑先核对原许可绑定的源码、计划、故障、任务范围及恢复轮，再复用该结果并执行当前诊断校验；调用配置或传输身份变化不重新执行同一个已完成诊断。即使调用缓存后来被新响应覆盖，原完成结果与待处理授权仍保持一致，新响应保留用于追溯。缺少原绑定、结果不完整或实际输入变化必须保留现场并阻止复用，不能以清空授权或重置计数绕过。未完成的调用继续按原调用身份恢复；新的诊断仍需新的动作许可。

证据有效性与检查成功分别判断。控制器校验源码、环境、命令、运行输入、原始退出码及报告完整性，并从归档 JUnit 重新核对用例集合和结果；有效的失败报告可证明其中部分用例通过，不能据此验收整项任务。IssueLedger 以任务血缘、检查命令、问题类别和用例身份记录机器故障；新观察逐项打开或关闭问题，关闭必须附证据。未执行、过期和缺失证据记为待复验，不因缺席而关闭问题，也不直接计作已证实退步。此类不可比较证据不能产生进展奖励。问题标识与动作预算分离，拆分问题不产生新额度。

一次验证收集所有可独立执行的检查，不在首个测试失败后隐藏类型检查、构建或其他套件的问题。构建生产者失败时，不执行声明消费其输出的检查，也不使用磁盘上的旧产物；记录 process_exit_code=null、prerequisite_failed 和 not_executed。阻塞关系按声明输入/输出传递，独立检查继续执行；源码或执行输入遭到改变时停止继续使用该候选。未执行记录不能冒充测试失败或通过。最终候选的有效检查同时刷新对应已验收任务的证据状态，不增加实现轮数。

当前范围内的实现缺陷由责任任务修复。集成检查可定位已完成的上游任务；跨任务修复须给出每个任务的源码路径、依据和证据引用，控制器核验既有任务及允许范围，不因重新打开已有任务而要求 PlanPatch。后继保留实现并复验；如果后继已经有独立的待修复问题，不得被另一次上游恢复降级为仅复验或覆盖其故障反馈。契约范围、依赖或检查命令需改变时才生成 `PlanPatch`，包含 `base_revision`、故障引用、任务增改/删除和交付检查契约。控制器校验版本、覆盖、DAG、原验收条目、测试命令义务和 `expected_tests` 下限，再由独立审查确认最小范围及测试语义。改名/拆分继承原 `origin_id`，不允许合并预算血缘；删除任务必须有同血缘替代覆盖，也不删除源码。最终候选仍执行所有任务检查、最终检查和运行探针，不降低整棵源码指纹匹配要求。

修复目标路径与事实引用分别校验。当前故障责任任务的候选文件可能尚未生成或已随门禁回退移出当前树；只有故障保存的任务与当前已接受计划完整一致、目标引用该任务或其检查、路径同时落在 allowed_paths 与本任务实际检查依赖的输入范围内且给出修复理由时，才允许把缺失路径作为候选修复目标。仅有写入范围、历史可见路径或模型提案不能建立这项依据；其他任务仍需当前文件证据。目标只可为公开的规范字面文件／子树，不能为通配符、私有路径或阶段所有合同。该判断不声称路径已存在、历史材料已齐或修复正确，不增加事实引用、不扩大 ActionPermit；正式授权仍绑定源码、计划、故障及任务范围，实际应用继续经过路径保护、测试变更独立审查及完整新鲜检查。拒绝反馈指出具体任务、路径下标和缺少的依据，文件未生成本身不要求修改计划。检查失败记录保留当时的完整任务合同；缺少旧合同的历史记录不能凭当前计划反填授权。输入范围复用实际执行的构建依赖编译器，包含任务消费产物所需的直接和传递生产者输入，不包含无关 runtime_prepare，也不信任故障或模型声明的额外命令。

任务分别记录实现状态（pending/in_progress/accepted/needs_repair）和证据状态（absent/valid/stale/failed）。恢复动作在当前并行批次全部返回、成功结果集成后执行；工作区身份绑定任务版本和基线 SHA。修订前保存旧计划、任务状态、未完成候选快照及审查；SQLite 用基线版本 CAS 事务激活。Git、计划文档和数据库之间使用可恢复日志，不声称跨系统原子提交。重启重放已激活日志不会再计费或再次重开任务。计划文档及候选的未知用户改动会阻塞自动覆盖。

真正需要回到设计等上游门禁时，也在失效事务内归档将被移除的结构化检查点，包括旧计划、未应用提案和任务状态；已有计划版本递增一次。上游门禁回退与局部修订都保留预算血缘及可追溯历史，重复恢复不会重复递增。

保留未完成工作区不等于继续使用旧依赖版本。重新派发时先核验候选指纹并保存私有快照，再并入当前集成基线；干净合并后重新检查，避免把已修复的上游问题再次当作下游缺陷。冲突时保留旧工作区、快照及公开候选源码，在当前基线的新隔离工作区内按原任务范围修复，并沿用原预算。Git 合并已完成而 SQLite 尚未记录时，用精确父提交和干净工作树核验后继续，不重复合并。部分已准备补丁先按前后映像恢复；补丁以外的改动或缺少必要身份的旧状态阻止自动覆盖。纯改名且目标、范围、验收不变的已验收任务继承实现，只需复验。

`RecoveryPolicy` 独立于编排、传输与验证，依据控制器事实提供允许动作集合。`DecisionRequest.kind=recovery_action` 带当前故障、当前允许作用域、历次方法及真实结果、业务/工程进展和累计消耗。决策结果仍为 approve / answer / ask_user；恢复批准必须通过 selected_action 选择已提供的动作，并说明 reason、evidence_refs 和 expected_result。期望结果不是已验证证据。未知动作、未知引用、越界目标或状态漂移都不得应用。决策阶段 `decision` 使用用户 `deep` profile。已校验的确定性动作不增加无必要的决策调用。既定技术事实的澄清不受其他任务停滞影响，未知事项及业务选择仍交用户。

任务候选已存在且当前原型内容、动作与原始人工批准匹配时，恢复候选提供 `prototype_recheck`：控制器重放既有动作、重采图片并独立复核原型证据，然后恢复原任务候选的验收。该动作不回退原型生成、不修改计划或实现、不重新询问设计批准；生产检查不能代替原型补证。许可绑定源码、计划、原型身份和人工来源，发布开始后不可用。浏览器报告和审查分别持久化，中断复用已完成步骤；采集或审查失败保留原任务及审批，形成新的故障观察。成功只关闭被独立复核的原型问题，任务仍需重新审查，生产检查按正常有效性规则复用或复验。升级前未回答且无许可的恢复请求可在原依据不变时增补此候选，经新决策及原有 CAS 事务生效；旧拒绝结论、已回答问题、许可、计数和候选历史保持原义。

任务因生产预览缺证被拒绝、已有实现候选及有效原型批准时，恢复提供 `preview_recheck`。控制器从已接受计划历史与门禁回退归档提供完整合同链：以最近一次门禁回退保存的已接受合同为本轮基线，保留之后每个不同的已接受版本及当前版本；没有门禁归档时使用全部已接受版本。重复内容按合同指纹去重，更早归档的来源索引仍保留，不纳入被拒补丁。每个版本提供完整动作、命令、路由、来源、计划及合同指纹，并提供固定执行视口（1440×900、390×844）。独立比较须覆盖链中每个历史版本的每个操作与断言，以 source_preview_hash 与原动作下标绑定到当前动作的逐项映射；遗漏最早合同、重复映射或未知版本均不得通过。旧单前驱映射只在确实仅有一个比较源时兼容，并审查命令、路由、隔离及清理义务；不能以动作数量增加证明保留。比较未通过或映射不完整不启动预览。比较通过后复用或执行已声明的任务检查和构建准备，在新隔离实例执行完整生产预览，保存逐动作结果、完整图片、源码、构建输入及环境身份、进程停止和临时目录清理回执，再交原任务独立审查。应用数据的收尾仍须由合同动作及断言证明，实例销毁不能替代。原件缺失、执行失败或清理未确认不推进任务；再次执行须取得新许可并完整重启。已保存比较及报告可续用，已开始却无耐久完成记录的执行保持占用，不能盲目重放写操作。源码、合同、审批或构建输入漂移拒绝旧证据；已有人工回答不扩大为新动作。该路径解决任务验收先要求预览、而正常预览安排在任务之后的依赖问题，不提前批准最终交付。

决策证据引用可以使用所提供 evidence 的顶层名称、真实存在的嵌套路径及数组索引、其中的产物 hash，或控制器已登记的故障引用；不要求只引用顶层名称。提案正文和模型自行列出的引用不能扩充控制器事实目录。纠错反馈提供具体字段、错误类型及允许范围，不回显任意 provider 错误正文。同一恢复决策因自身调用产生的 token 记账变化继续复用原始请求快照；故障、历史结果、实现消耗、候选范围及状态身份变化仍形成新请求。旧版仅因引用校验而回退人工的请求，可以在原依据不变时重新校验最后一次已保存响应，不重新调用模型、不重置次数；仍须通过许可事务和人工回答优先检查，不能从较早响应中挑选批准。

引用目录区分控制器记录与未验证提案。failure.proposal.changes 等实际提供的结构化路径可作为未验证提案引用，用来讨论拟议改动；其正文中声称的产物 hash、URL 或文件名不能因此成为事实引用。恢复批准、技术事实回答及诊断必须同时引用控制器记录，不能仅凭提案批准；每个跨任务修复目标也须有控制器依据并匹配既有路径范围。引用提案不应用补丁、不改变验收状态，保护测试的独立评审和真实检查继续执行。校验版本 3 可重新核对旧版因拒绝提案路径而回退人工的最后一次响应，保留原拒绝记录、实际调用次数和人工回答。

`RecoveryCycle` 保存恢复过程，`ActionPermit` 保存具体动作、范围、输入身份、授权来源及 reserved/started/completed 状态。许可、状态 CAS、并发人工回答检查和审计回执在同一 SQLite 事务中提交。动作前持久化预留与开始状态，动作后绑定真实结果；同一请求重启复用许可及结果，新失败观察重新决策。无法核实完成的动作保留占用，不能当作未执行自动退款。自动许可只覆盖一次具体动作及其必要验证；新的人工确认可覆盖展示范围内的一轮诊断（含一次纠正）、一次局部修订或每个所列任务一次修复及验证，超出范围重新授权。旧单步确认不扩大含义，人工回答优先。自动授权标记 rule/agent，不写人工 answer；决策调用每个请求最多一次响应加一次格式纠正。原型审批、认证、资源及权限变化、业务选择和发布后例外保留人工边界。

旧配置补齐缺失阶段/自动化字段，原值和文件保持不变；被取消的次数限制在启动提示和 status 中明确标注。既有未完成运行采用新决策策略，不重置历史计数、人工审批和已验收结果。工程里程碑的旧记录只建立基线，不追溯奖励。普通 worker 的调用身份不加入恢复账本字段。旧诊断只有输入身份完全匹配时才复用已落盘结果。待答的旧次数授权问题只在新有效许可提交后失效；已回答的旧授权按原含义使用。显式暂停仍需用户续跑。关闭 automation.enabled 后需要模型判断的恢复交人工，确定性规则继续工作。status 和交付证据包含恢复轮、许可、来源、消耗和进度账本；发布后的恢复保留独立日志和预算。

阻塞摘要同时报告当前检查状态、未通过用例、独立审查 findings、环境错误及诊断校验错误。全部测试通过但截图或 README 未满足审查时，明确展示“检查通过＋独立审查未通过”；无记录、未执行、证据无效和实际失败分别表达，不再用“尚无有效失败报告”覆盖不同状态。

状态数据库版本为 8，支持从版本 1–7 迁移。只有 run 持控制锁后执行迁移，先备份，再事务保存原始记录、任务血缘及历史计数。旧二进制拒绝新状态版本；只读 status/logs 不迁移。版本 6 的进度、人工问题和未完成候选原样保留，工程里程碑先建立保守基线。迁移和重启不重复计费或执行已完成动作。

规划输入包含当前任务来源映射、已消耗的任务预算及尚未解决的规划审查意见。首次登记只在没有历史来源和任务预算时成立；存在预算而来源记录缺失时必须阻塞恢复。控制器完成来源校验和登记后，规划审查使用登记后的映射及校验结果，不能沿用规划生成前的空映射。历史失败反馈保留，但不替代当前控制器事实；来源校验通过也不替代独立的规划质量审查。审查拒绝时保留完整问题、证据和修复要求。

恢复保证到可以核对的操作边界，不保证恢复单个模型请求内部的 token 位置。提交、集成和其他副作用先核对已有结果，再决定是否执行。

## 环境与回收

aa2 使用 autoagents 或本项目 Conda 环境，目标依赖不装进 aa2 环境。目标项目内按依赖指纹共享只读环境，工作区专属安装和版本冲突使用不同环境。安装期间不修改被其他任务使用的环境。

PlanResult 的 `environment_file`、`requirements_file` 仅表示工作区根目录相对路径，例如 `environment.yml`、`requirements.txt`；空字符串表示自动发现，不能填写 YAML 正文或包列表。规划阶段验证路径格式并将错误反馈给规划任务，文件可由后续负责的实现任务创建；环境准备时再检查文件存在与工作区边界。清单选择字段不会触发源码写入，也不会按内容猜测或回退到其他清单。

EnvironmentManager 的安装后依赖检查和环境证据采集需要目标前缀内的 Python 与 pip。项目 Conda 清单可以只声明 Node 等业务依赖；控制器在临时清单中仅补充缺失的 python=<environment.python_version> 和 pip，不改项目文件，不覆盖项目已有的 Python/pip 版本、渠道或构建约束。实际解析结果仍须通过原有安装、完整性、来源和业务检查。补充工具的版本化声明参与环境指纹，不能复用旧的未补工具解析锁；未受影响的完整清单沿用原指纹。安装后缺少目标 Python 可执行文件属于环境工具链故障，不得从宿主 PATH 借用解释器，也不应误报源码状态冲突；失败实例和日志保留，新实例核验通过前不发布就绪记录。

原生 Python、Conda base、全局 npm 和全局 shell 配置保持隔离。缓存和浏览器资源位于受管理目录。Docker 不属于首期必要运行条件。

环境准备还将当前安装前缀的完整 pip/Conda 锁、Python 安装包的版本、Requires-Python、Requires-Dist 与 extras，以及 Conda 的 depends/constrains 归档为 environment_resolution 证据。记录绑定 installed environment hash 和原始锁摘要，公开文本沿用凭证脱敏；不执行新的解析或安装，不把元数据当作兼容性批准。每条真实 CheckResult 携带该引用，任务、最终、复用、重集成审查及恢复沿现有检查证据通道读取；缺失、损坏或环境身份不匹配不能复用。旧环境无需重装即可读取实际安装元数据，旧检查在 verification-v13 下保留为历史并重新执行，不补写其成功记录。

环境解析工件还保存版本化 `capture_scope`，与规划、审查、实现及恢复提示共用同一有限采集范围声明。完整安装锁和包元数据不等于完整求解过程：现有采集器不记录求解器后端、有效渠道顺序/优先级、合并求解设置和配置 pin；公开记录明确为 `not_collected`，不能推断为不存在、默认值、安全或不必要。该声明不读取宿主配置，不改变环境身份、安装行为、读写权限或检查门槛，也不把旧工件补写成具有新历史事实。重检只运行既有准备、采集和检查，诊断文字不能扩展其能力。若模型派生的已批条款错误要求未实现的控制器采集能力，应追溯原需求和具体版本，通过既有 `contract_corrections`、独立语义审核和真实复验纠正；明确用户要求或实质必要证据仍须阻塞，不能根据范围声明直接忽略。

Python 准备在真实 pip install 成功时保存官方 `--report` JSON 和完整脱敏安装输出，发布就绪记录前将其绑定到安装前缀完整性；公开 environment_resolution 验证报告中的包版本和运行时与实际安装元数据一致，并提供 ABI、安装构件地址/已有哈希、请求 extras 和真实构建输出。报告只覆盖本次 pip 事务选择的发行包，Conda 已满足的包仍由完整显式锁与元数据覆盖；报告不是锁，也不枚举隔离构建环境，源码构建的依赖及结果须按实际安装输出审查，缺失的事实不推断为已验证。没有安装历史的旧前缀明确记为 not_recorded；再次准备时使用既有解析锁建立新实例，保留旧实例和历史证据，不以重跑当前元数据伪造过去的构件来源。新记录缺失、损坏或与当前包/解释器不符时不得发布成功证据；报告和安装输出沿原有脱敏及内容寻址通道交给独立审查，控制器不代替语义验收。

任务工作区的 Conda 清单被解析器明确拒绝（包版本不存在或约束冲突）时，保存失败候选和阶段故障，由恢复策略诊断并授权修正清单，再重新准备环境及验收；尝试仍按原始任务血缘累计。不能根据宿主机已安装版本推断 Conda 渠道存在对应包，也不能静默放宽版本约束。暂时性网络失败结束单次重试后可重新决策；权限、锁文件重放和用户配置默认环境的失败保留阻塞恢复语义。

项目声明 Playwright 时，EnvironmentManager 使用该项目锁定的 CLI 安装匹配浏览器，默认 Chromium；`environment.playwright_browsers` 可配置 chromium、firefox、webkit。目标命令使用 `PLAYWRIGHT_BROWSERS_PATH=0`，浏览器位于项目 node_modules 内，安装完成后才保存 Node 就绪记录，浏览器内容也计入依赖完整性和检查输入身份。目标运行环境采用无头模式，不继承 DISPLAY、WAYLAND_DISPLAY、XDG_RUNTIME_DIR 等桌面会话入口，避免 WSLg 干扰渲染帧；不修改宿主会话变量或放宽沙箱权限。VerificationService 仅执行检查，不安装浏览器；静态原型检查继续使用控制器自己的浏览器环境。

ResourceManager 只管理登记的资源。步骤、任务、阶段完成及恢复时触发回收，每六十秒补扫。默认可再生缓存上限十 GiB、闲置期限七天、最低可用磁盘五 GiB。自动与手动 GC 使用同一规则。

私有 Git exclude 与源码采集对嵌套生成目录采用一致规则，包括 `frontend/node_modules`、构建输出和 Python 缓存。恢复既有工作区时幂等补齐排除规则；已跟踪源码和未知未跟踪文件仍受未归档改动检查保护。新 npm 项目的缺失锁文件由 EnvironmentManager 使用真实 npm 解析生成，不要求模型手写依赖图或完整锁文件。

必要恢复数据、有效审批、需求规格和交付证据不能当作临时文件删除。先保存并核验产物，再回收工作区和一次性测试数据。

## 日志与验收

日志包含时间戳，已知总量显示真实进度，同一活动原行刷新。token 按 run 累计，沿用 provider 的原生 total 口径，缓存与思考 token 单列且不重复相加，缺失用量明确标记。事件记录保留模型/环境/人工等待的时间边界，检查证据记录执行耗时；完整的各阶段性能分析面板留给后续版本。

执行任务前显示当前计划的任务总数和已验收数量，每次派发显示“正在执行第 N/M 个任务”、任务 ID 和标题。序号按当前计划顺序固定，并行任务分别记录；重试与续跑不递增序号，重新规划后使用新计划的总数和顺序。这些展示事件不推进验收门禁。成功结束（包括再次查看已完成迭代）后显示项目目录、已准备环境的启用命令和运行文档路径；有应用预览契约时输出可复制的预览命令和访问地址，明确提示预览与日常运行的数据保存方式可能不同。缺少运行环境入口时指向 README 安装与启动说明，暂停或取消不显示成功运行指引。

步骤切换保留上一行的结果和耗时，新的步骤另起一行；多个并行活动分别显示。活动行显示运行时间、真实进度、距最近输出的时间；无输出时不虚构时间。五分钟无输出仅作当前行预警，不能判断卡死或推进门禁。输出观察归属具体调用或活动，界面刷新不算输出，过期调用事件不得污染新活动。普通文件日志不追加心跳。模型诊断仅输出安全分类，不包含原生配置或凭据。

Provider 诊断流中出现 `timeout` 或 `timed out` 不能作为整个调用超时的证据，不显示“provider 报告等待超时”。成功调用不附带失败诊断；失败诊断优先依据结构化错误，内部诊断关键词不覆盖实际结果。原生 `input_too_large` 或明确的输入长度拒绝显示为“provider 输入超过 CLI 长度上限”，不因同一诊断流中的连接或超时关键词自动重试；人工提示要求处理实际问题，不一律归因为配置或认证。

Codex CLI 的 `turn/start` 单次输入上限为 1,048,576 个字符（已在本机 0.163.0 验证），与 64,000 字符软目标分开处理。传输适配器声明原生上限；不超限的请求保持完整内联，超限时将完整编译请求按 UTF-8 原样写入本次调用的只读 `prompt.txt`，只向 CLI 发送包含路径、字符数和内容摘要的读取指令，要求分块读到 EOF 后执行。派发前必须通过原生文件读取能力探针并核对文件完整性；不截断需求、研究正文、验收条件或 schema。材料清单同时记录完整请求及实际入口的身份与字符数，读取能力不代替任务验收。该方式仅处理原生输入硬限制，不为达到软目标改变普通请求的读取步骤；模型上下文容量仍由用户所选模型决定。文件沿用调用资源的保护与回收生命周期，恢复重建新文件，原始需求、候选和失败用量保留。

选择题仅接受列出的 y/n 或数字，空输入不得默认批准。长文本回车换行、Ctrl+D 提交，支持多行粘贴、方向键与跨行删除；输入期间停止动态刷新。所有入口共用答案校验。原型候选及应用前后指纹必须先持久化，文件应用、浏览器检查、独立审查完成后启动预览并展示通过/修改选项。拒绝后单独收集修改意见。审批绑定实际查看的版本；暂停恢复复用未改变候选与证据，刷新预览链接。旧版提前询问审批的问题保留历史并退出待回答列表，不得被当成正式批准。

终端问题按显示列宽换行，正确计算中文宽度，完整问题输出到可滚动记录，再显示输入提示，不能裁掉长诊断或允许范围的行尾及超出一屏的段落；持久化问题原文和回答语义保持不变。相同的恢复理由不重复展示。

必须验证未完成迭代拒绝新建、同文及同义需求去重、部分差异规划、旧实现回归、证据缺失、部分文件应用恢复、审查期间恢复、provider 切换、用量去重、环境不串线、活跃资源不误删、原型版本审批和最终候选一致性。

## 首期实现约束

Node 首期使用 npm，已有 pnpm/yarn 工程不会自动改写。Conda 与 Python 依赖清单应分开声明，本地/editable pip 依赖通过 requirements 文件进入独立环境。默认识别项目根目录以及 backend/frontend/api/web；其他布局可以在任务中声明 cwd、环境清单和启动命令，新增生态需扩展 ProjectProfile/EnvironmentManager。

规划审查、候选测试修改审查、原型审查和最终实现审查使用不同的验收标准，避免把“尚未实现”误判为规划缺陷。新原型必须记录所选设计的固定版本 URL；既有原型修改由已审查规格中的 prototype_paths 限定。README 阶段不能覆写已经确定的规格、架构和控制器证据。

## 自动合并与可恢复交付

候选源码指纹与主目录实际执行指纹分开记录。Git 不会复制主目录原有的忽略文件；发布后不能直接将包含这些文件的主目录整体指纹与候选指纹比较。新迭代将入场执行输入清单与基线在同一事务中保存。交接时逐项核对候选的已验证文件，额外文件必须未跟踪、仍被忽略、不是旧基线中的跟踪文件，并且与入场清单一致。旧迭代没有清单时，仅允许用不可变 Git 基线和保留输入重建出原始 project_source_hash；无法证明时保留现场，不能只凭文件扩展名或 gitignore 放行。

证明成立后保存 publication_inputs 绑定，保留原 source_hash，另记录主目录完整的 runtime_source_hash。没有从 tree_hash 全局排除数据库、忽略文件或其它运行输入；运行检查及收尾仍绑定主目录的真实完整输入。新文件、源码变更、保留输入内容变化或绑定损坏继续阻止交接。旧基线包含无法重建的链接时拒绝兼容推断，新入场快照可以保留完整执行身份。发布后重启复用该证明和原预算，数据库等原有文件不删除、不重建、不覆盖。

每轮固定目标分支和已提交基线，开发仅在 detached worktree 中进行。新空仓库默认 main；已有仓库按本地存在的 origin/HEAD、唯一 main/master、唯一分支选择，有歧义才询问。选择持久化到 delivery.target_branch；运行中改配置不改当前目标。不再创建公开的 aa2/<run-id> 分支；状态格式迁移不改变既有迭代的交付目标。

主目录必须干净，且目标分支未被其它 worktree 占用。干净目录可切换到目标分支；未提交、暂存、未跟踪修改和发布路径上被忽略的文件均受到保护。已跟踪的 .env 等文件不会因排除规则被从候选中删除。禁止自动 stash、reset --hard 或 git clean。

候选验收完成后，DeliveryCoordinator 保存目标旧 SHA、候选 SHA/tree、验证身份、文件前后 Git 对象、索引身份、环境引用及 phase。发布使用受保护的 fast-forward 和主目录更新，不直接裸写分支而遗留旧工作树。Git、文件系统和 SQLite 不构成单一事务；恢复核对日志可归因的前后映像和索引状态，未知状态等待人工处理，不能覆盖用户更改。

目标分支前移时先在隔离工作区重新合并。冲突候选需要独立审查，合并后重新执行完整验收与最终审查；原型变化重新取得绑定指纹的人工批准。delivery.max_reintegrations 默认 2，已用计数跨重启保存，可显式增加上限。发布后的新用户提交不自动回退，需要人工核对。

PlanResult.runtime_prepare 声明候选与主目录需要的构建，也为消费产物的任务提供前置构建；runtime_probes 声明轻量且不修改用户数据的运行探针。有前端复用 PreviewSpec 进行短期服务检查，检查结束停止服务。主目录复用已验证的项目内 Conda 环境，editable 源码位于该环境内部；Node 用已验证 package-lock 执行 npm ci，不允许在主目录重新解析锁或改源码。安装器与构建只能写明确生成目录。缺失声明或需要源码修正必须在隔离工作区验收后处理，不通过开放主目录写权限绕过。

运行入口 .aa2/runtime.sh 与 runtime.json 指向项目内已准备环境，生成 README 同时保留独立安装方法。Store 在同一事务写入完成回执、当前环境引用并标记 SUCCEEDED。发布开始后取消只暂停收尾，不回滚源码、不允许开始新迭代。环境失败保留发布日志，普通 run 继续收尾。

完成回执关联原始需求、规格、设计、审批、最终检查与审查、任务结论、用量和运行环境。ResourceManager 先验证回执，再释放本轮运行引用、回收工作区、按预期 SHA 删除本轮私有 Git 引用，并压缩重复检查点、删除登记且已无引用的中间产物。共享产物、未完成迭代及未登记路径不能被误删。当前交付环境有单独 pin，不受缓存 TTL 或压力回收。回收失败保持 SUCCEEDED 和 cleanup_pending，下次启动或手动 GC 用同一逻辑重试；不执行 git gc --prune=now。

## 2026-10-14 质量优先修订

实现与兼容细节、审核项对照及验证边界以 [质量优先修复记录](quality-first-implementation.md) 为准。累计 token 只作计量，不作为停止条件；字符软目标不能削减权限、schema、验收义务或失败证据。

采用单一生产呈现路径：同次请求的相同研究快照正文只内联一次，各声明、版本与来源完整保留，不依赖历史会话补全。目录分页、历史摘要、证据精简和通用压缩模式移出当前范围，没有备用生产分支或启停开关。

诊断日志按实际消费者保留，临时副本及时清理；归档正文失去最后消费者后可回收，结构化验收证据持续保留。活动调用、未完成阶段、开放问题和恢复必需日志受保护。释放必须有耐久记录，意外缺失仍是证据错误，不能放宽门禁。

## 2026-10-15 OCR 边界修订

原型检查器版本 3 要求实际页面及声明路由在 1440、390 两个视口均有完整动作和可核验 PNG 产物；审批只采用校验后的审查布尔值。原始人工决定保留，旧自动证据重新采集。`verification-v7` 在归档前使用不跟随链接的文件描述符验证报告类型与 32 MiB 上限，解析与归档使用同一份字节；可执行文件归属按解析后的路径判断。证据评估及复用必须提供 ArtifactStore，输入读取或准备失败返回不可复用。

恢复完成和后继恢复/门禁转移共用一次 Store 事务，状态格式迁移遵循下方 v6 修订。交付修复绑定触发观察及候选身份，未完成补丁按原始映像恢复，新失败不能复用已完成修复。每轮重新从已接受计划编译检查；同一源码、命令和环境输入的自动复验只有一次额度，观察 ID、日志地址和耗时变化不产生新额度。主目录运行预算独立持久化，`delivery.max_runtime_retries` 默认 3；反复失败与未知旧预算的处理见 operations.md。

研究网络传输在连接边界固定已校验的公网 IP，保留原主机名作 HTTP Host 和 TLS 校验，并逐跳限制重定向。原型和应用浏览器共用仅能连接当前预览端点的本地代理，禁止未经授权的其他来源、WebSocket 和 service worker。请求拦截本身不能证明浏览器重定向被隔离。

研究资料抓取遵从控制器环境中的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 和 `NO_PROXY`（兼容小写变量，小写优先），支持 HTTP(S) 代理。代理是用户指定的传输入口，可位于本机；资料目标仍必须全部解析为公网地址。向代理发送的 CONNECT 目标固定为已校验的数字 IP，代理不能重新解析资料域名；原域名仍用于 Host 和 TLS 证书校验。代理认证只进入代理握手，不进入资料请求或错误消息。代理配置无效或连接失败不得静默改走直连。Fake-IP 地址仍被拒绝，须在 DNS 配置中使用真实 IP 解析；人工重试重新解析和采集，保留已保存的模型候选。

计划修订先保存每个候选快照的 checkpoint intent，再执行 Git 提交，随后事务性推进快照与集成基线。恢复先核对 intent，不能把未知用户提交当作控制器提交。`verification_only` 修订与恢复均重新执行覆盖检查；实现待处理标志本身不能否定已满足需求，也不能作为放行证据。检查点子树删除使用字面前缀，删除记录与归档集合一致。所有控制器 Git 命令使用隔离环境和字面文件名。

本地需求只读取无链接的普通文件，支持 UTF BOM，读取上限 4 MiB，辅助进程采集时限 30 秒。下载后解析、研究材料发布和附件归档均在受管辅助进程中进行，进程结束得到确认前保留资源保护。HTTP deflate 使用有上限的原始输入，在 zlib 解码无效时从头尝试 raw deflate，不混入失败尝试的输出。

每条检查的附件默认上限为单文件 64 MiB、合计 256 MiB、256 个文件，归档时限 120 秒；`attachment_capture` 可配置。目录项和深度也有界限，读取前检查实际文件大小，复制过程中继续计数，拒绝链接和特殊文件。采集记录保存策略摘要、实际计数、失败原因及现场位置；超限/超时是证据采集失败，不是业务缺陷。检查继续完成互不依赖的命令，再进入 `WAITING_USER`。只有上限或录制输入发生变化才能复验，同配置下的重复答复不会自动重跑或增加业务修复额度。

新增的 `test_diagnostic` 明确表示普通诊断附件，可在生产者、待审消费者、读者和未解决问题均不再使用时立即回收；JUnit、结构化检查结果、源码/环境身份、人审证据，以及用途不明的历史 `test_attachment` 保留。相同字节还有必需用途时保留实体。采集失败的 scratch 由持久化 hold 固定；同源码/命令的成功替代观察落盘后才释放。归档上限不等于测试运行期间的磁盘配额，仍须进行磁盘监控。

检查到审核之间采用持久待审消费者：任务、最终/复用、重集成各自仅保留当前观察。单条检查在采集恢复发布和临时资源清理前转交所有权，批次状态与消费者在同一事务保存；复用已有观察时由临时读者桥接并发回收，再登记持久消费者。独立审核结果及问题证据先落盘，消费确认与阶段审核结果事务性保存，旧观察的确认不能释放新观察。暂停、异常和崩溃重启保留待审消费者，完成/取消、阶段失效、受影响或移除任务的计划替换释放对应保护；归档历史不继承待审所有权。已按策略回收的旧附件若需新审核，必须通过既有恢复授权取得真实新观察；缺失或损坏不能冒充正常回收。运行时检查没有模型审核消费者，不因此延长附件寿命。

手工恢复快照在任何锁创建前检查源和锁路径，锁经目录描述符无链接打开。复制清单涵盖所有实际复制的文件、目录模式、链接目标和文件摘要，包括 Git、artifacts、visuals、cache；复制后和源端结束时再次对照，只有明确的基础设施定位字段允许重写。交付烟雾验证在 GC 后真正启动生产预览并执行桌面/移动端浏览器断言；清理失败不跳过其他清理动作。

真实 Next.js 16.4.0 交付验证补充：`.next/server/route-cache` 是首次访问会写入的运行缓存，和既有 `.next/cache`、trace 一样不属于不可变构建摘要；`server/app`、chunks、构建清单及其他文件继续参与校验，不能用缓存豁免掩盖服务代码变化。显式声明某个缓存子路径为命令输入时，仍校验该路径内容。


历史源码比较同时保留控制器实际观察到的公开文件版本。`source_history` v4 从同一 run 的既有历史采集检查点读取原始 `current` 槽，核对清单与源码身份、正文哈希和类型，并按当前敏感路径及范围重新筛选；不沿模型引用、提案或嵌套历史递归扩展。相同源码与文件按最早真实采集来源合并，新的历史清单不产生重复观察或无限缓存失效。旧 v1–v3 采集的原件保持不变，已有未提交候选可作为只读比较材料恢复，无须伪造 Git 提交或历史审核回执。

观察记录提供完整选中文件和至当前选中文件的真实差异，沿既有证据索引供实现、保护审查、任务/最终审查及诊断按需读取。记录绑定来源清单和源码哈希，但不表示已应用提案、已验收版本或时间顺序，也不替代检查与独立审核。观察没有完整路径清单，未捕获的文件或比较端不能证明不存在；未记录版本仍是证据缺口。正文缺失、损坏或同一源码身份下内容冲突必须保留候选并阻塞，不能静默忽略或以当前测试通过替代历史断言审查。
