# Demo4 后的有限恢复契约与可见行为优化

基线：`f4ad2ec`。执行机：LAPTOP-UE3M8TAU / Ubuntu-20.04；Python 与 aa2 使用仓库 `.conda-env`。先设计，后实施；本文不授予任何产品、网络或系统配置权限。

## 已确认问题及目标

1. `EnvironmentManager._command` 将未知外部非零退出置为普通 AA2Error，顶层 `known_exception` 将其视为内部故障。只有 DependencyResolutionError 携带结构化命令证据；npm 包装、基础设施重试和任务外边界会丢失其他类型的同类事实。Demo4 的 npm 崩溃与后续证据补传证明了这条共享链的重要性。目标是完整保存失败观察、保守区分归因与权限，不给未知错误增加自动修复权。
2. `diagnosis_actions` 复用执行候选并手动追加最终 repair/阶段重入。最终任务归属提案已经修通，但类型和描述仍把提案和执行混在一起，交付诊断另有目录适配。目标是两类表示明确分离，仍复用原先的状态可用性计算、严格 adjudicate、许可和执行前版本校验。
3. Demo4 的 DOM 文本断言漏掉隐藏提示；当前控制器 `design.exercise(expect_text)` 同样只调用 to_have_text。目标是用户交互中的 expect_text 同时验证可见性，版本化自动浏览器结果；并在计划、实现、测试保护审核和最终审核中明确“文本存在/测试全绿”不替代可观察行为。这里不声称代码能证明任意业务语义。

## 范围、非目标和现有调用图

安装命令：Conda 创建/重建、pip install/check、npm 锁生成/ci、产品浏览器安装及环境工具查询 → `_command` → typed exception → Engine 任务恢复 / 有限基础设施重试 / 外部 prerequisite。原型浏览器安装使用独立 subprocess 路径，接入相同失败观察，保留其原有重试策略。

恢复：任务/最终 `RecoveryController.resume` 与交付恢复入口 → 提案目录 → `adjudicate` → `RecoveryPolicy.authorize` → ActionPermit → 分派及失效复验。候选目录表示可供正式授权的具体动作，不表示已经授权；只有持久许可才表示授权。

浏览器：原型和实现预览共用 `exercise`；自动审批身份和预览合同已有 browser_version。生成产品自己的测试由 aa2 编写并受原保护审核约束。

不引入 DSL、全工作流重写、新审计保留机制、新模型配置、无界重试、清缓存、依赖升级或系统网络变更。不修改已交付 demo1–4，不强制迁移其历史。只在隔离目录读取 Demo4 原件作回放。内部不变量失败、损坏证据、权限违规仍保留原严格边界。

## 修复 A：安装失败观察和完整交接

### 表示与错误语义

- 在现有安装证据模块增加有限、版本化的失败观察构造/归档辅助。记录受控 argv、cwd、进程结果（非零退出/超时/启动失败）、退出码、流采集状态与不可变引用；已有 runtime/source 身份在其责任层补充。不得把未知数据写成空的成功图。
- 增加明确的外部环境命令异常；DependencyResolutionError 保持兼容并共用证据承载。RetryableInfrastructureError 兼容旧无证据调用，也能携带本次命令事实。未知外部非零退出进入外部 prerequisite，不自动按依赖错误授权；已识别依赖错误继续现有任务诊断，已识别暂时故障继续原有限重试。
- 单独保留失败观察和原因分类。无法识别原因不等于控制器实现有 bug；反之 Python TypeError、恢复绑定冲突、成功退出后的身份不一致不能伪装成外部非零退出。
- 旧 evidence version 1 与旧异常构造继续可读；只对新观察写入新字段，不重写冻结请求、已答问题、许可或累计次数。

### 采集和消费者

- `_command` 的真实外部失败均携带同一观察；非机器流沿用安全完整归档。机器输出成功时保持原解析返回值，失败时才归档脱敏输出；超时明确记录未完成采集，不把部分流标成完整，也不将正常取消当失败。
- npm 自有 debug 目录对所有携带环境命令观察的异常补充同一安全归档；保持不跟随链接、不采信 stderr 任意路径、数量/字节上限和敏感过滤。包装必须保留原异常类别，不按调试文本授予权限。
- Engine 已有 environment_failure 是任务证据的统一落点；基础设施重试记录同时保留观察，后续决策看到的是当次失败而不是只有字符串。任务外 prerequisite 保存观察及已归档引用；只增加新记录的事实，不改变旧问题绑定。
- 当观察缺失、采集不可用或日志不完整时明确标记，允许真实后续核对，不伪造原件。一般日志采集器的取消/资源错误不在本轮改成自动成功。

### 风险与验收

主要风险是误授予重试/修改权或把正常取消计失败。反例必须覆盖权限/认证/完整性/磁盘/未知输出、网络、取消、内部异常；确认当前的默认安全边界和次数不变。引用损坏、私有文件、超限仍拒绝或明确不可用。原故障日志在只读模型视图可读但不可写；重复恢复保留相同事实绑定。

实现核验补充（修复 A）：真实 `Engine.start` 暂停重入反例发现，旧入口先重执行阶段，才再次遇到 prerequisite；新采集产生不同日志 lease，导致同一失败出现第二个待答问题。对此只为新版外部命令观察持久化等待指针，在重新执行前重放原问题和原证据；确认只允许重新核对，不代表安装成功或修复权限。指针与等待计数在确认后原子清理；拒绝/暂停继续保留。旧无观察问题和其它恢复机制不迁移、不改写。补充未答不重跑、否决保留、答复后真实重验与中断恢复测试。

独立审查补充 A2（并发等待）：`collect_batch` 保留异常对象，但 `_develop` 只上抛首个异常；未归类安装错误又未进入 `_task` 的依赖恢复落点，其他任务的原始等待会丢失。仅在任务调用边界新增窄捕获，在批次聚合或取消前同步保存每任务观察、原计划/任务/候选身份和有限待处理集合。相同命令事实发生在不同任务不能共用答复。单一当前问题沿用原绑定；启动时先处理全部原始等待，再恢复阶段执行。确认只原子移除对应项并累计原计数，历史观察不删除；拒绝、中断、不同任务和新一次失败均不偷用旧确认。已识别依赖错误仍走原诊断，内部错误仍内部，未知错误不获得修改依赖权限。验证实际双任务 Engine + 小型真实失败进程、混合结果、批次取消、确认落盘后中断、旧单等待兼容及损坏绑定；不搭建通用队列系统，不发起真实双安装。

## 修复 B：提案目录和正式执行候选分离

- 提供专门的有限提案描述类型：动作、责任阶段、任务提示、所需校验和“只可提议”语义，不包含可伪装为 ActionPermit 的授权字段。原 `allowed_actions` 键保留，供旧诊断兼容，但新值使用提案表示。
- 从现有可供授权的动作集合投影提案，再在同一小入口加入既有“先定位责任任务”的最终 repair 和原有阶段重入规则。交付诊断通过相同投影，保留其不同的发布边界。
- `RecoveryDecision`/许可仍由 adjudicate、authorize 构造。明确拒绝将提案对象直接交给授权/分派。模型自由文字、目录项或非空 task_id 都不能代替责任路径与事实证据校验。
- 完成旧诊断重验时使用同一种提案投影；旧保存的 dict 目录仍按原会员校验兼容，不扩大其动作。原冻结权限、候选摘要、已答问题保持原语义。
- 本项不改变哪些动作有权限执行，不改变预算、调用次数和未发布/已发布规则。接口表示变更后补真实调用者组合及中断恢复回归。

## 修复 C：可见文本和业务断言

- 控制器 UI 动作 `expect_text` 明确成为“同一次观察中可见并具有预期文本”。`expect_visible` 保持原行为，不新增通用条件语言。
- 提升自动浏览器检查身份版本。原人工批准仍只绑定原内容与动作；旧自动结果不能冒充新检查，在正常恢复需要时重新检查/审核。已完成项目不主动启动或迁移。
- 对计划、实现、测试变更审核、最终审核提供一致的有限指导：可见提示需要可见性断言；持久化需要刷新/新上下文；导入导出需要实际文件和全部字段；失败/取消需要原状态未变。仅针对原需求，不强塞新业务义务。
- 补实际浏览器负例：DOM 内有正确文字但 display:none/visibility:hidden，原代码可通过、新代码必须失败并保留失败动作；可见文字可通过。通过实际原型/预览入口验证，不仅 mock locator。另保留最终 green checks 后独立语义拒绝、责任任务修复和复验链。
- 控制器不对生成测试任意做文本扫描来“证明正确”；模型审核依旧有局限。截图或单次浏览器通过也不证明所有状态。

独立审查补充（修复 C）：版本 7 的两个独立断言仍会接受可见容器中隐藏后代的 `textContent`，也可能把早先的可见状态与稍后的隐藏预期文字拼成成功。共享执行器改为一次重试断言，在同一浏览器观察中解析可见目标并比较渲染 `innerText`，复用现有 Playwright 机制。自动证据升为版本 8，版本 6/7 都需重验，原人工同意绑定不变。原型与应用预览均补真实隐藏后代、动态隐藏、可见嵌套文本、延迟显示和节点替换正反例，不新增通用条件框架。

独立审查补充 C2（交付完成重入）：`completion_pending` 只复核命令证据和运行输入；重新审核原型不等于重新检查发布后的应用。通过显式回调将 Engine 现有浏览器检查身份（协议及已配置缓存身份）交给 DeliveryCoordinator。应用运行检查记录实际开始时的身份，结束时核对未变化；交付复用身份包含该值，完成前要求应用证据也具有相同值。旧证据缺值或身份变化使用现有 `_invalidate_completion`，保留原件、已发布提交、人工批准、累计预算，重新检查仍消耗原有预算。不重开 SUCCEEDED，不更改无预览项目的身份。仅新增这一个跨层依赖，不在交付层复制浏览器缓存逻辑。验证真实 Engine 重入 + 实际命令/Chromium、缺失/改变/未改变、最后预算、已成功终态和检查中身份变化；原审核脚本的内存注入只作为旧失败证据，不冒充真实发布复验。

独立复审补充 C3（有限文字语义）：版本 8 无条件 innerText 破坏原生 input button/submit 的 value 标签和无 innerText 的 SVG。最终版本 9 采用一个同步浏览器观察：唯一元素、当前布局可见性、当前文字和匹配同时计算；只在这个完整观察外沿用 10 秒动作重试，不把不同时间的条件拼接。HTML 使用原生 innerText；input button/submit/reset 使用 value 标签；SVG 使用具有实际 Range 布局矩形且 computed visibility 可见的文字节点，排除隐藏后代及不呈现的 title/desc。其它命名空间不退回 textContent。字符串区分大小写、精确匹配，沿用 Playwright 的空白折叠及 U+200B/U+00AD 处理，保留其它 Unicode。display:contents 按子布局判断。它不证明遮挡、透明度、对比度、裁剪或 SVG 字形变换等像素效果，不实现完整渲染引擎。6/7/8 自动证据均需正常重验，人工内容绑定不变。验证原审查全部输入与上述元素的正负例、动态隐藏/替换、原型及应用入口，保留失败动作和截图。

## 验证矩阵和提交

| 链路 | 正向 | 必要反例/重入 |
|---|---|---|
| 安装分类 | npm 锁/ci、Conda、产品浏览器；实际非零退出的完整流与身份 | 未知/认证/权限/完整性不是依赖修复；内部异常仍内部；取消不计失败 |
| 证据交接 | 实际 Engine、ProviderRouter 只读挂载、基础设施重试、阶段外 prerequisite | 缺失/损坏/超限/敏感/链接；旧字符串证据；暂停恢复绑定 |
| 恢复目录 | 任务、最终无 task_id、交付入口；具体 repair 后正常授权 | 目录不能直接授权；未定位任务/越权/陈旧引用/发布后拒绝；旧请求和单次分派 |
| 用户可见行为 | 原型与实现预览中的可见文字、实际文件与状态断言指导 | 隐藏正确文本失败；旧 browser_version 不复用；语义拒绝仍阻止交付 |

先运行旧代码反例和各子系统定向/相关回归；每个独立修复经验证与差异审查后本地提交。最后运行完整 pytest、Ruff、diff 检查，绑定源码摘要和工作区。独立代码审查重点看安全边界、遗漏调用者和兼容性；若发现问题，修复后复验，不以测试数量代替审查。全量纯等待可交低成本监督。

优先复用已有 Chromium 缓存与小型隔离夹具，不重装前三个 demo；本轮不额外永久删除。记录起止空间，但不把逻辑大小与 D 盘物理变化等同。发现需要扩大架构范围或不确定权限语义时，停止依赖改动并报告。

## Demo5 的后续验证安排

三项优化提交并全量通过后，选择两任务以内的本地单页工具，由 aa2 自行形成计划和实现。初步候选为“本地阅读摘录卡”：标题、摘录、标签，编辑/删除确认、搜索筛选，持久化，schemaVersion 1 JSON 导入校验→数量预览→确认原子替换、完整导出；非法/取消不改数据、可见反馈；桌面与移动端。无账户、后端、同步、图片或 AI 内容生成功能。

正式启动前核对目录不存在用户工作，写需求及可测验收输入，记录空间和版本基线。控制器故障反例留在隔离测试，不故意污染产品依赖或计划。原型需真实检查；若没有适用于该新原型的批准，提交父会话处理。区分 aa2 外部源码修复、人工替代决策、正常用户审批、aa2 自主修复、精确缓存命中；本场景通过不等于长期稳定性统计证明。
