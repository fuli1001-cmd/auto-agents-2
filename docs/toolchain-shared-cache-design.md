# 工具链预检与共享依赖缓存设计

日期：2026-10-22。设计基线：`7d1f32cd2719258cbcb05cce03b3727e4042b7a2`。

## 依据与目标

demo2 恢复曾丢失启动进程的 Conda/Node 工具链，直到环境准备才报 `Conda not found`。现有 doctor 仅判断 Conda 是否可找到；未知 AA2Error 会被归为控制器内部错误。预检应报告可操作的环境前提，不能替代恢复授权或自行更改 shell、代理、TLS、认证。

当前 npm/Conda 缓存按项目保存，pip 缓存随临时目录释放；Node Playwright 使用 `PLAYWRIGHT_BROWSERS_PATH=0`，控制器原型使用项目 `.aa2/cache/browsers`。demo 1.58.2/build1208 与 demo2 1.55.1/build1193 不可混用；三个原型缓存均由控制器 Python Playwright 1.63.0 要求 build1243。只校验主程序不足以证明整个目录完整。

目标：提前检查本次操作实际需要的工具；显式启用同用户、同主机缓存；共享下载缓存与匹配的不可变浏览器制品；维持环境、源码和可变状态隔离；保留现有门禁、证据和恢复计数。

非目标：审计保留、跨用户/远程缓存、全局环境、共享 node_modules、模型配置修改、统一现有项目依赖、系统包/代理/TLS 修改、通用缓存平台。不得改动已交付 demo/demo2。

## 现有调用边界

- WorkflowEngine.start → 恢复/阶段执行 → EnvironmentManager.ensure/install_node/with_resolution。
- EnvironmentManager._prepare 使用 Conda 创建独立 prefix，保存解析锁、安装来源与完整 prefix 身份。
- install_node 使用锁文件 npm ci，准备浏览器后保存 Node 完整性标记。
- VerificationService / application preview 在 SandboxRunner 中运行；input_entry 跟随链接计算真实依赖字节，input_identity 已包含 Node 安装树。
- _ensure_browser 为原型和控制器应用预览准备 Python Playwright 浏览器；现有判定仅查任意 Chromium 文件。
- ResourceManager 只管理项目内部登记资源；共享目录不能伪装成项目内部资源。

## 预检设计

增加小型 toolchain 模块，分两层调用，不引入新业务验收：

1. 控制器启动/恢复及 doctor：记录实际 Python executable/prefix/version；验证 Git、配置的 Conda 和当前 provider 的解析路径及必要解释器；执行有限时长的只读版本探针及已有 sandbox probe。输出结构化缺项、修复建议和环境身份，不输出环境变量、原生配置或凭据。原型 Playwright 缺失列为按需前提，非 GUI 项目不因此被拒。
2. 环境操作：创建 prefix 之前检查 Conda；已选择的项目解释器核对实际 prefix；需要 Node 时检查该 prefix 内的 node/npm；浏览器安装验证实际驱动的期望路径及完整产物。已经可以正常安装的缓存缺失属于 cache miss，不转成人工批准。

真实缺失/错误解释器使用明确的 ToolchainUnavailable 类型，进入现有 external_input 前提恢复边界；网络错误仍沿现有基础设施重试；依赖 manifest 求解冲突仍可由产品候选修复。未知异常不统一包装成网络故障。重试重新执行预检，肯定回答不能使缺失工具变成可用。

预检不执行模型请求、不安装工具、不更改全局环境。使用调用进程实际 PATH；可显示正确激活/配置路径的建议，不猜测或自动替换用户工具链。预检结果是环境事实，不是兼容性或最终验收批准。

## 共享配置与兼容性

添加显式 `shared_cache` 配置：默认关闭，启用后使用当前用户专属版本化目录（默认 `~/.cache/auto-agents-2/v1`），允许明确指定绝对目录用于隔离测试。旧配置读取、现有项目路径和已有证据保持兼容。本轮仅在新 demo3 中启用。

目录必须为本用户拥有、无链接跳转、非组/其他用户可写的真实目录。缓存根、下载区、制品区、索引/引用/锁分离。专属根必须在项目之外且不包含项目；首次初始化加跨进程锁和所属标记，拒绝收编非空未登记目录。配置只决定缓存位置，不授权模型读取其他项目数据。

## 下载缓存

复用 npm/pip/Conda 自带缓存格式及其锁定/包校验机制；不改锁文件和安装来源。Conda 继续 copy 到项目 prefix，不把环境文件硬链接到可变共享缓存；npm ci 仍创建各自 node_modules。

安装器仅取得指定下载种类目录的写入能力。SandboxRunner 增加限定缓存写挂载：校验显式启用的根及固定 downloads 子目录，其他共享路径一律拒绝；provider 和检查不会得到这项写能力。按种类持有跨进程锁，清理不能与安装同时执行。初期接受同种安装串行的性能取舍，避免另建复杂并发调度。

共享缓存不是可信安装环境；来源、包锁/完整性与安装报告仍由原安装流程记录。损坏和权限错误保留现场，不降低 TLS 或包验证。

## 浏览器制品

使用对应的实际 Playwright 驱动进行安装，不使用全局 latest。期望身份包括驱动版本/浏览器清单、请求的浏览器族、平台/架构及系统兼容信息。完整 manifest 覆盖发布目录的每个相对路径、类型、执行位、文件内容；拒绝逃逸链接、特殊文件和不完整安装。清单身份与完整内容身份分开记录。

一个安装过程为：取得该期望身份的进程锁 → 校验已发布对象 → 命中时登记引用 → 未命中时在隔离临时目录执行官方安装器 → 核验该驱动实际期望的可执行文件、安装完成标记及完整目录 → 发布新不可变对象 → 原子更新索引与引用。部分安装不发布；损坏的旧对象保留，新对象不原位覆盖它。

对象发布后文件和目录只读；索引和引用位于独立的控制器目录。既有项目缓存不自动导入，也不移动/删除它们。真实首次下载形成冷样本，之后命中形成热样本；如日后增加导入，须独立证明完整目录，不能只比较主程序。

Node 保留 `PLAYWRIGHT_BROWSERS_PATH=0`，只将专用 `.local-browsers` 入口连接至已验证共享对象，node_modules 其余内容保持私有。就绪标记及检查输入继续通过 input_entry 计算链接目标的全部字节。SandboxRunner 仅对本项目已登记且身份正确的浏览器对象增加只读挂载；未知路径、其他项目引用及不完整对象不开放。

原型选择控制器驱动匹配的对象，记录实际版本/内容身份，不能以任意 `chromium-*` 文件存在判定就绪。原型与应用预览的证据保存实际浏览器身份，复用必须匹配；人审内容批准与自动浏览器证据保持不同职责，环境变化要求自动重验，不伪造新的人工批准。

## 引用、清理与恢复

浏览器引用包含项目、run（如有）、消费者位置和对象身份。索引、发布、引用与 GC 使用同一控制锁协调；安装完成到消费者可见之间不能出现无保护空窗。

- 未完成/暂停/待答运行及无法核实状态的引用继续保护。
- 仍存在并指向该对象的项目入口继续保护，包括交付目录。
- 进程仍在使用或清理未确认时保护。
- 一个项目删除/释放入口只影响自己的引用，不删除对象；只有全部引用已明确失效才能回收。
- 不按时间推断一个未知引用已经失效。不扫描/删除用户原有缓存。

共享 GC 采用显式入口和 dry-run，独立于项目 ResourceManager 的目录删除。初期只回收能够证明无引用、过期的已登记对象和闲置下载缓存；锁忙、状态损坏、路径异常一律保留并报告。不会为了满足空间指标删除有效引用。共享清理本轮仅显式调用，不自动套用项目容量预算；失败暂存目录保留。控制器浏览器绑定也作为有效入口保护，直到明确被替换。复用当前清理期限概念，不增加审计保留策略。

## 验证矩阵

1. 预检：缺 Conda/PATH、错 prefix、缺 Node/npm、provider 必要解释器缺失、只读版本探针失败/超时、凭据不输出；真实 engine 恢复仍停在有效前提，纠正环境后继续且不清计数。
2. 下载缓存：两个项目使用同一缓存而安装树独立；锁竞争、取消释放、清理与安装互斥；非法根/链接/共享制品写挂载拒绝。
3. 浏览器：冷安装、第二项目命中且安装器未调用；不同驱动/平台/浏览器族不误命中；同身份并发只发布一次；缺文件/改字节/部分安装/链接逃逸拒绝；旧对象保留。
4. 真正的沙箱：检查能读取登记对象，写入失败；其他共享目录不可见；实际 browser launch 使用期望构建。
5. 证据：共享对象改变使 input identity/reuse 失效；合法命中保持完整证据；Node 就绪仅在浏览器发布后成立；原型自动证据绑定浏览器身份。
6. 生命周期：运行暂停、重启、原型复验、交付目录使用、工作区清理、两个项目共享与单方释放；未知/损坏引用保守保留。
7. 所有已有适用回归、ruff、diff check、pip check 和最终全量；源码摘要核对实际被测版本。

测试使用少量真实工作流与故障注入组合，不构造所有状态的笛卡尔积。真实缓存测试使用隔离目录和同机实际官方安装器/浏览器，不更改 demo/demo2。

## 本机验证记录（2026-10-22）

使用指定 `.conda-env` 在两个独立临时项目实际准备依赖，未调用 provider、未改 demo/demo2。控制器 Playwright 1.63.0/build1243 的内容摘要为 `4b8905d243548e8c796377ac00af24ba3dd2a88693bd4f3511b17ed22e14f1f1`，实际 Chromium 为 153.0.8010.12；项目 Playwright 1.58.2/build1208 的内容摘要为 `00311ff4938a9ff54367ceecf28b3db10ca19c0171ef60c9af79fad8a2f6f5e3`，实际 Chromium 为 145.0.7632.6。

两种驱动各完成一次发布，第二项目浏览器安装器调用为零；Conda 前缀、解释器 inode 和 node_modules 包文件 inode 不同，共享对象路径和内容身份相同。两边实际浏览器启动与 DOM 断言、沙箱写入拒绝、重复 ensure/install_node 不重新执行安装命令均通过。下载阶段一次工具连接中断，原安装进程清理确认后重试；173,161,474 字节的未完成 ZIP 仍保留，未作为有效制品或空间节省。

浏览器文件的逻辑大小分别为 687,911,949 和 649,989,359 字节；按 `st_blocks * 512` 统计的文件分配块分别为 689,831,936 和 651,948,032 字节。这些是共享对象文件测量，未包含目录/文件系统开销，不是通过删除旧项目释放的磁盘量。

真实临时项目还发现所选 Conda Node 依赖前缀中的 `libnode.so`。共享浏览器安装入口现明确接收完整所选运行前缀的只读挂载，不能依赖宿主目录猜测；原型使用自包含驱动目录。对应真实沙箱回归验证库可读但不新增写权限。另覆盖清理抢锁后目录重建、旧浏览器入口移除不再授予挂载且仍须正常准备。
